## 一、迭代方式

每个阶段按同一个循环走，**演示验收通过后才进入下一阶段**：

1. **阶段开工前**：补全该阶段规格，并写好"演示脚本"（你将点哪些按钮、应该看到什么）和验收标准，由你评审
2. **开发**：按任务拆分，一个任务一个分支一个 PR，自动测试全绿才能合并
3. **演示**：运行 `make demo`，你在浏览器里按演示脚本亲手走一遍
4. **验收记录**：把结果写进 `docs/acceptance/phase-N.md`（通过 / 问题清单），问题进入待办
5. **打标签**：验收通过后在 main 上打 `phase-N-demo` 标签，作为可回退的稳定点
6. **反馈调整**：你的意见先改规格，再改代码，不直接口头改需求

两条硬规则：
- **没有演示脚本的阶段不开工**
- **每个涉及用户可见功能的任务，必须同步更新演示数据和演示脚本**，否则不算完成

## 三、各阶段演示成果（草案，开工前评审定稿）

演示环境：`make demo` 启动，浏览器打开 `http://localhost:8069`（后台）；网站用主机名区分品牌：`qclub.localhost:8069` 与 `aushare.localhost:8069`。演示数据全部是**假数据**，与真实桌台、价格无关，仅存在于本机一次性的演示库。

### 阶段 1：后台管理演示（✅ 已验收，定稿脚本见 `docs/demo/phase-1.md`，结果见 `docs/acceptance/phase-1.md`）
演示脚本：
1. 用管理员登录，打开 Billiards 菜单，看到演示桌台（Chinese 8-Ball、Snooker、9-Ball）
2. 在 Settings 修改押金比例、取消窗口等，保存；输入非法值（押金 150%）被拒绝
3. 查看 Opening Hours：周五、周六到 2:00 AM (+1 day)，其余日到 12:00 AM (midnight)
4. 手动新建一条预约（日期 + 整点下拉，保存前即显示价格和押金）：押金自动 = 台费 × 比例；再建一条同桌重叠预约，被拒绝并给出英文提示
5. 建一条营业时间外的预约，被拒绝
6. 修改桌台单价，已有预约的价格不变，新预约用新价格
7. 把锁定时长改成 1 分钟，建一条 Awaiting Deposit 预约，约 1–2 分钟后自动变 Expired，同时段可重新预约

验收：本阶段 31 条规格（含 ADM）在报告里全部有测试且通过；上述演示脚本能走通。
说明：权限和 AUSHARE 隔离（SEC、ISO）由自动测试和 `make iso-check` 验证，不单独演示。

### 阶段 2：顾客预约演示（草案，开工前评审定稿）
演示脚本：
1. 不登录打开 `qclub.localhost:8069/billiard/booking`，能看到占用网格，看不到任何他人信息
2. 用演示顾客账号登录，选日期、选桌、选连续 2 小时，页面显示价格和应付押金
3. 选择距离开始不足 24 小时的时段，支付页出现 "This booking cannot be cancelled free of charge."
4. 提交后该时段进入 Awaiting Deposit 并锁定；用无痕窗口另开一个顾客，看到该时段置灰；强行提交同一时段，提示 "This time slot has just been taken. Please choose another."
5. 周五晚选 11:00 PM – 次日 1:00 AM，页面、确认文案显示正确（如 "Fri 23:00 – Sat 01:00"）
6. 锁定到期后时段自动释放
7. 打开 `aushare.localhost:8069/billiard/booking`，返回 404
8. 员工在后台把该预约手动确认为"已确认"（Stripe 接入前的替代操作，将来电话预约也用它）

验收：阶段 2 的 12 条规格全部有测试通过；演示脚本走通；在手机浏览器上看网格是否可用（人工项）。
说明：本阶段**没有真实支付**。

### 阶段 3：约球演示（规格待编写）
演示脚本（草案）：顾客 A 预约并经员工确认 → A 在该时段下发约球帖 → 顾客 B 回复并申请加入 → A 确认 → 页面只显示昵称 → 预约被取消后帖子自动关闭 → 未登录用户只能看不能发 → 员工举报处理、删帖、封禁。

### 阶段 4：完整资金流演示（规格待补全）

说明：全程测试模式，不涉及真实资金；GST 待会计确认后再加入。Stripe 的付款确认可能需要把 webhook 转发到本机，阶段 4 开工前验证。

## 七、穿刺（Spike）计划

穿刺：用很小的代价、在固定时间内先验证最大的不确定因素，产出**结论**而不是正式代码。阶段 1 完成后（2026-11-05）整理如下。

### 规则

1. **限时**：每个穿刺半天到一天，超时就带着已有结论回来讨论
2. **只交结论**：结果写到 `docs/spikes/<编号>-<名称>.md`（格式见 `docs/spikes/README.md`）：问题 → 做了什么 → 结论 → 对规格 / 设计的影响；试验代码不合并进 main
3. **结论回到规格**：穿刺推翻了某个设计时，先改规格和设计说明，再改代码
4. **涉及生产的由你执行**：Claude Code 不连接生产库（AGENTS.md 红线），只准备命令、检查表和备份恢复步骤；在生产上只做**只读**检查

# 穿刺（Spike）记录

穿刺：用很小的代价、在固定时间内先验证最大的不确定因素。规则和清单见 `docs/progress.md` 第七节。

## 文件命名

`docs/spikes/<两位编号>-<英文短名>.md`，编号与 `progress.md` 第七节清单一致，例如 `00-production-environment.md`。

## 每份记录的格式

```markdown
# 穿刺 N：<名称>

日期：YYYY-MM-DD　执行：<谁>　限时：<半天 / 一天>　结论：**可行 / 不可行 / 有条件可行**

## 一、问题
要回答的具体问题（来自 progress.md 第七节）。

## 二、做了什么
步骤、命令、环境。涉及生产的只写只读检查；不贴密钥、密码、客户数据。

## 三、结果
原始结果的摘要（可附表格）。

## 四、结论
一句话结论 + 理由。

## 五、对规格 / 设计的影响
需要改哪些规格编号、设计说明、任务拆分；没有影响也写明"无"。

## 六、遗留问题
还没回答的部分，以及下一步。
```

## 原则

- 试验代码不合并进 main（如需保留，放在 `spike/<编号>-<名称>` 分支，不开 PR）
- 涉及生产环境的检查只读，由你执行；Claude Code 不连接生产库
- 不记录任何真实密钥、密码、客户个人信息

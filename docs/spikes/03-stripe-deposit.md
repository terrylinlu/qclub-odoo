# 穿刺 3：Stripe 押金流程

日期：2026-11-12　对应：任务 4.1（`docs/design/4.1-stripe-spike.md`），规格 `docs/spec/phase4.md` 第 A 节和第 H 节第 1、3 条
结论：**可行，用 Odoo 自带的 Stripe 模块**。押金付款、服务端确认、付款失败、3D Secure、原路退款都已用测试卡实测通过；会计凭证按做法 A 跳过是**必须的**；有 3 项要在任务 4.2 的设计里处理（第四节）。

## 一、环境

- 穿刺库 `qclub_spike_pay`：演示库（已是两家公司）的副本，安装 `payment_stripe`，Stripe 支付方式建在 TAB Entertainment 下、只对 Q Club 网站生效，状态为测试。
- 测试密钥从本机仓库外的 `~/.config/qclub/stripe-test.env` 读取，以环境变量名传入容器；付款通知的签名密钥由 Stripe 命令行工具生成，保存在同目录的 `stripe-webhook.env`（只有你本人可读）。全程没有打印密钥，仓库和日志中没有密钥。
- 付款通知：Stripe 官方命令行工具 `stripe/stripe-cli:v1.55.3`（Docker），把 Odoo 处理的 8 种事件转发到本机 `/payment/stripe/webhook`。
- 付款用 Stripe 公开的测试卡，在浏览器里实际操作。
- 穿刺结束后已删除穿刺库（里面存有测试密钥）。

## 三、遇到的问题

1. **Stripe Link 挡住付款。** Stripe 账号默认开启 Link（快捷支付）。Odoo 预填了顾客邮箱，付款表单就出现 Link 注册区并强制要求手机号，付款还没发到 Stripe 就失败了（"Your phone number is incomplete."）。你已在 Stripe 测试后台关闭 Link（2026-11-12），之后一切正常。**生产账号上线前也要关闭**，或者到时另行决定。
2. **没有做法 A 时，退款通知会报错。** 穿刺服务器本身没有跳过凭证的逻辑，收到退款通知时又去生成凭证，返回 500。所以做法 A 必须写在模块里，服务器处理每一个通知时都会经过它。
3. **Odoo 通用付款链接的校验码不绑定预约编号。** 同一个顾客、金额、币种的校验码，可以拿去付另一个编号。正式实现不使用通用付款链接，改用本模块自己的付款入口，由服务端按预约生成交易（PAY-003、PAY-011）。

## 四、任务 4.2 的设计要点

1. **自己的付款入口**：确认页的 Pay deposit 进入本模块的付款页，服务端按预约的押金、币种、公司生成交易，交易关联预约；浏览器不能改金额，也不能为别人的预约付款。
2. **付款成功的处理**：在交易的后处理里确认预约，重复通知只处理一次；付款到达时预约已过期，按 PAY-006 恢复或自动退款。
3. **做法 A**：关联 Q Club 预约的交易（含退款）不生成付款凭证；其他交易不受影响。
4. **测试环境**：模块依赖 `payment_stripe` 后，测试基础库也要先装上它，才能和生产一致、`make iso-check` 才无差异。这要修改 `Makefile`，在 4.2 设计里请你批准。
5. **本机演示**：`make demo` 之后用脚本从密钥文件配置 Stripe，并启动通知转发；脚本放在仓库的 `tools/` 下，不含任何密钥。

# qclub_billiard 需求规格：阶段 4（押金支付、退款、未到场、现场结算、对账）

放置路径：`docs/spec/phase4.md`　状态：**已定稿**（2026-11-11 评审通过，第 H 节 9 个决定均按建议批准）
每条需求必须有至少一个测试，测试名或 docstring 中带编号（如 `test_pay_004_webhook_confirms_once`）。
本阶段新增前缀 PAY 和 CO（第 J 节，2026-11-11 增补并批准），并启用 `docs/spec/phase1-2.md` 第 F 节预留的 RF、NS、ST；第一个编码任务把 CO、PAY、RF、NS、ST 加入 `tools/make_report.py` 的覆盖检查。
界面文字为英语，示例文字以本文件为准。金额统一用 AUD 和 Odoo 货币舍入（AGENTS.md）。

**一句话**：顾客在网上提交预约后用 Stripe 付押金，付款成功预约自动变为已确认；之后按规则取消退款、未到场没收、到店后现场结算余额；员工每天能核对当天的资金。

**全程测试模式**：只用 Stripe 测试模式和测试卡，不涉及真实资金（AGENTS.md 红线 3）。

## A. Stripe 与押金支付（PAY）

| 编号 | 需求 |
|---|---|
| PAY-001 | Q Club 使用**独立的 Stripe 账号**，在 Odoo 中配置为一个只对 Q Club 网站生效的支付方式。AUSHARE 的结账页、支付方式列表和页面输出不变：`make iso-check` 无差异，并有测试确认 AUSHARE 结账页看不到该支付方式 |
| PAY-002 | 测试密钥只来自本机仓库外的文件 `~/.config/qclub/stripe-test.env`，由脚本写入测试库或演示库；仓库、日志、测试报告中不得出现密钥。只接受 `pk_test_` / `sk_test_` 开头的密钥，遇到 `_live_` 立即拒绝。自动测试和 CI 不连接 Stripe，用模拟的 Stripe 响应 |
| PAY-003 | 待付押金的预约，确认页显示 **Pay deposit** 按钮和金额（= BK-009 的押金）；点击后进入 Stripe 付款，付款页显示 Q Club 名称、预约编号和时段 |
| PAY-004 | 只有服务端核实付款成功（Stripe 通知或服务端查询，不信任浏览器跳转回来的参数）后，预约才自动变为**已确认**；记录付款金额、时间、Stripe 交易号。同一笔付款的重复通知只处理一次 |
| PAY-005 | 实收金额或币种与预约押金不一致时不确认预约，记录异常并在后台标出，交员工处理 |
| PAY-006 | 付款成功到达时预约已过期（锁定期刚好结束）：时段仍空闲则恢复并确认；时段已被他人占用则自动全额退款，并发邮件说明 |
| PAY-007 | 付款失败或顾客取消付款：预约仍为待付押金，锁定期内可重试；不会重复扣款。已确认的预约不能再次付款 |
| PAY-008 | 付款成功后发 Q Club 版式邮件 "Deposit received – booking confirmed"：押金金额、时段、免费取消截止时间；不含卡号等支付信息 |
| PAY-009 | 后台预约表单显示付款信息（金额、时间、Stripe 交易号、退款、没收、结算），只读；任何人不能直接改这些金额 |
| PAY-010 | 员工在后台手动确认（电话预约等）保留，预约标记为 "No online deposit"；这类预约没有可退或可没收的押金，结算时全额收取（第 H 节第 5 条） |
| PAY-011 | 付款、退款记录带 `website_id`；顾客只能为自己的预约付款，不能通过改参数为别人的预约或别的网站付款 |
| PAY-014 | 重复付款：同一预约已有一笔成功付款后又到账一笔，不自动退款；预约标记 "Payment needs attention"，后台可筛选并在表单醒目提示，同时发提醒邮件到 Q Club 联系邮箱；由管理员原路退回多付的金额，必须填写原因，记录操作人和时间。预约已付押金后服务端拒绝再创建付款（2026-11-12 你的决定） |

## B. 取消与退款（RF）

RF-001、RF-002 见 `docs/spec/phase1-2.md` 第 F 节，本阶段实现。

| 编号 | 需求 |
|---|---|
| RF-003 | 顾客可在 My Account 的 My bookings 和确认页自行取消待付押金或已确认的预约；确认前先显示结果，如 "You will receive a full refund of $20.00." 或 "Your $15.00 deposit is non-refundable."（第 H 节第 2 条）；确认取消成功后，页面刷新时必须显示一条明显的提示（如 "Booking cancelled."），不能只是静默刷新（2026-11-13 验收时发现并修正） |
| RF-004 | 取消窗口按快照值计算：开始前**大于或等于**窗口时长取消为免费取消；员工在后台取消同样按此规则 |
| RF-005 | 管理员可在窗口内取消时例外全额退款，必须填写原因；员工没有这个权限 |
| RF-006 | 退款通过 Stripe 原路退回，记录退款金额、时间、Stripe 退款号、原因、操作员（ST-002）。Stripe 退款失败时预约仍取消，退款标为失败并在后台提醒，可重试 |

| RF-008 | 待付押金的预约取消时没有付款，不退款也不没收 |

| 编号 | 需求 |
|---|---|

## D. 现场结算（ST）

ST-001、ST-002 见 `docs/spec/phase1-2.md` 第 F 节，本阶段实现。

| 编号 | 需求 |
|---|---|
| ST-005 | 已到店的预约在后台点 **Settle**：实际台费默认等于预约台费，可修改（加时、优惠等），修改时必须填写原因 |
| ST-006 | 余额 = 实际台费 − 已付押金。余额大于 0 时选择 EFTPOS 或现金（只记录方式和金额，不连接刷卡机）；余额等于 0 直接完成；实际台费少于押金时按第 H 节第 4 条处理 |
| ST-007 | 结算后预约变为已完成，结算记录不可修改；如需更正，由管理员操作并记录原因 |

## E. 日对账（ST）

ST-003 见 `docs/spec/phase1-2.md` 第 F 节，本阶段实现，口径如下。

| 编号 | 需求 |
|---|---|
| ST-008 | 后台 **Daily Reconciliation** 按营业日（6:00 AM 分界）汇总当天发生的资金事件：押金收取、押金退款、押金抵扣、窗口内取消没收、未到场没收、现场 EFTPOS、现场现金；每个数字都能点开看到对应的预约和记录 |
| ST-009 | 资金事件按**发生时间**归属营业日：付款计入付款当天，退款计入退款当天，抵扣和现场收款计入结算当天，没收计入置为未到场或取消当天 |
| ST-010 | 报表显示两个自检等式，不相等时标红：① 押金收取 − 押金退款 − 押金抵扣 − 两项没收 = 未了结押金（已付、尚未退款 / 抵扣 / 没收）当天的净变化，后者按预约记录独立计算；② 当天结算的实际台费合计 = 押金抵扣 + EFTPOS + 现金 |
| ST-011 | 报表可导出为 Excel；只有员工和管理员能看，带 `website_id` 隔离 |
| ST-012 | 第 G 节 5 个场景的数字由自动测试逐项核对 |

ST-004 改为：**押金收取时不计 GST**（2026-11-11 你确认）。没收押金和押金抵扣台费这两个时点的 GST 待会计确认；本阶段报表只记录金额，不生成税务凭证；税率保持后台可配置，代码中不写死。

## G. 对账场景（ST-012 的预期数字）

押金比例 50%，五个场景都发生在同一营业日。

| # | 场景 | 台费 | 押金 | 当天的资金事件 |
|---|---|---|---|---|
| 1 | 中式 2 小时，到店，按原台费结算，余额刷卡 | $50.00 | $25.00 | 收取 $25.00；抵扣 $25.00；EFTPOS $25.00 |
| 2 | 美式 2 小时，开始前 ≥ 24 小时取消 | $40.00 | $20.00 | 收取 $20.00；退款 $20.00 |
| 3 | 斯诺克 1 小时，开始前不足 24 小时取消 | $30.00 | $15.00 | 收取 $15.00；窗口内取消没收 $15.00 |
| 4 | 中式 1 小时，未到场 | $25.00 | $12.50 | 收取 $12.50；未到场没收 $12.50 |
| 5 | 美式 2 小时，到店后加时到 3 小时，余额付现金 | $40.00 → 实际 $60.00 | $20.00 | 收取 $20.00；抵扣 $20.00；现金 $40.00 |

当天合计：

| 押金收取 | 押金退款 | 押金抵扣 | 窗口内取消没收 | 未到场没收 | EFTPOS | 现金 |
|---|---|---|---|---|---|---|
| $92.50 | $20.00 | $45.00 | $15.00 | $12.50 | $25.00 | $40.00 |

自检：① $92.50 − $20.00 − $45.00 − $15.00 − $12.50 = $0.00，五个预约当天都已了结，未了结押金净变化为 $0.00；② 实际台费 $50.00 + $60.00 = $110.00 = $45.00 + $25.00 + $40.00。

## H. 已确认的决定（2026-11-11，均按括号内建议）

1. **付款流程**：优先用 Odoo 自带的 Stripe 支付模块，由穿刺 3 先验证它能否只收押金、关联到预约、支持退款；不行再直接调用 Stripe Checkout。同意吗？（建议：同意，先穿刺再定）
2. **顾客自助取消**：在 My Account 和确认页可取消，先显示退不退款再确认（RF-003）。同意吗？（建议：同意）
3. **会计凭证**：Q Club 与 AUSHARE 共用一家公司。本阶段**不在 Odoo 账簿里生成会计凭证**，只在本模块记录资金流水和日对账报表，避免影响 AUSHARE 的账；如果穿刺发现 Odoo 支付模块会自动生成付款凭证，单独为 Q Club 建一个日记账，并先停下来请你确认。正式接入会计等会计确认 GST 口径后再做。同意吗？（建议：同意，请同时告知会计）
4. **实际台费少于押金**：到店后押金不退，可抵扣实际台费，差额不退；确需退还由管理员走 RF-005 的例外退款。同意吗？（建议：同意，规则简单，也很少发生）
5. **没有在线押金的预约**：员工手动确认的电话预约保留，标记 "No online deposit"；未到场时没有押金可没收，只记录状态。同意吗？（建议：同意，阶段 5 电话预约要用）
6. **付款时预约已过期**：时段仍空闲就恢复确认，否则自动全额退款（PAY-006）。同意吗？（建议：同意）
7. **对账口径**：按营业日、按资金事件发生时间归属（ST-008、ST-009）。同意吗？（建议：同意）
8. **到店标记时间限制**：开始前 30 分钟到等待时长结束之间才能标记已到店（NS-005）。同意吗？（建议：同意）
9. **会计确认的事项**（不阻塞开发，结算和报表先只记金额）：没收押金是否计 GST；押金抵扣台费后，台费按含 GST 全额开票还是只对余额开票；台费价格是否含 GST
10. **两家公司**（2026-11-11 你的决定）：Q Club 由 TAB Entertainment Pty Ltd 经营，AUSHARE 由 AUSHAREU PTY LTD 经营。两个网站都还没有实际交易，改为按实际公司配置：新建 TAB Entertainment，把 Q Club 网站挂到它下面，网站结构不变（第 J 节）。第 3 条"不生成会计凭证"在本阶段仍然有效，等会计确认 GST 口径后再记入 TAB Entertainment 的账
11. **顾客账号**（2026-11-11 你的决定）：一个账号通用两个网站，从 Q Club 进入 AUSHARE 商城购物不用再注册；My Account 按网站显示各自的内容（CO-004）

## J. 两家公司（CO）

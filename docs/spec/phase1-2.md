# qclub_billiard 需求规格：阶段 1–2（基础模块 + 在线预约）

放置路径：`docs/spec/phase1-2.md`
每条需求必须有至少一个测试，测试名或 docstring 中带编号。

## A. 后台配置（CFG）

| 编号 | 需求 |
|---|---|
| CFG-001 | 管理员可在后台配置：押金比例（默认 50%）、免费取消提前时长（默认 24 小时）、未到场等待时长（默认 30 分钟）、未付押金锁定时长（默认 10 分钟）、最长连续预约小时数（默认 4 小时）、最多提前预约天数（默认 14 天） |
| CFG-002 | 配置值校验：押金比例在 0–100%；各时长不得为负；最长连续预约小时数 ≥ 1 |
| CFG-003 | 预约创建时，将当时的小时单价、押金比例、取消窗口、等待时长快照到预约记录；之后修改配置不影响已有预约 |
| CFG-004 | 仅"球厅管理员"组可修改配置，"球厅员工"只读 |
| CFG-005 | 后台开关"登录后才能查看占用情况"，默认关闭（即匿名可看）；开启后占用接口和网格对未登录用户不可用 |
| CFG-006 | 后台开关"网格显示台费"（Show Prices in Grid），按网站保存，默认开启；只有管理员能改。关闭后，预约网格的空闲格显示 "Available"，桌名悬停提示不含单价；顾客选中时段后的台费和押金摘要、确认页、付款页、邮件仍照常显示金额（2026-11-12 你提出并确认） |

## B. 桌台与营业时间（TBL）

| 编号 | 需求 |
|---|---|
| TBL-001 | 管理员可创建桌台：名称、类型、小时单价、是否启用、排序；桌台名称在同一网站内唯一 |
| TBL-002 | 桌台类型可配置（如中式八球、斯诺克、九球），不写死 |
| TBL-003 | 停用的桌台不可被新预约，已有预约不受影响 |
| TBL-004 | 营业时间按星期配置，可设置休息日；起止必须为整点；结束时间可晚于 24:00（跨午夜），跨午夜的时段归属于开始那一天；营业日以阿德莱德本地时间早上 6:00 为分界；开门不早于 6:00，关门不晚于次日 6:00；0:00–5:59 的整点属于前一营业日 |
| TBL-005 | 修改桌台单价只影响之后创建的预约（依赖 CFG-003） |
| TBL-006 | 跨午夜时段的每个小时格，在预约网格中显示在其所属营业日下，并标注"12:00 AM (next day)"等，避免用户误以为是下一天的预约 |
| TBL-007 | 提供初始营业时间数据（见下方"初始营业时间"），用于测试环境和首次配置参考；后台可修改 |

## C. 预约模型与规则（BK）

| 编号 | 需求 |
|---|---|
| BK-001 | 预约起止时间必须为整点，时长为整数小时，且不超过"最长连续预约小时数" |
| BK-002 | 预约必须完整落在该桌某一个营业时段内（允许跨午夜，如周五 23:00–02:00）；不在营业时段内、休息日均不可预约 |
| BK-003 | 不可预约已过去的时段；不可超过"最多提前预约天数" |
| BK-004 | 数据库层排他约束：同一桌、时间区间重叠的"有效占用"预约不能同时存在。有效占用状态：待付押金、已确认、已到店 |
| BK-005 | 并发测试：两个独立事务同时创建同桌重叠预约，恰好一个成功，另一个得到明确的冲突错误（在真实 PostgreSQL 上测试，不 mock） |
| BK-006 | 已取消、已过期、未到场、已完成的预约不占用时段，同时段可被重新预约 |
| BK-007 | 新建预约状态为"待付押金"，`lock_expire = 创建时间 + 锁定时长` |
| BK-008 | 定时任务（cron）：`lock_expire` 已过且仍为"待付押金"的预约，置为"已过期"并释放时段 |
| BK-009 | 押金 = 台费 × 押金比例，台费 = 快照单价 × 预约小时数；结果按 AUD 货币精度（分）四舍五入 |
| BK-010 | 状态流转只允许：待付押金→已确认/已过期/已取消；已确认→已到店/已取消/未到场；已到店→已完成。其他流转抛错 |
| BK-011 | 预约编号自动生成且唯一 |
| BK-012 | 预约记录带 `website_id`，由所属桌台继承 |

## D. 网站预约页（WEB）

| 编号 | 需求 |
|---|---|
| WEB-001 | 预约页 `/billiard/booking` 仅在 Q Club 网站（`website_id=3`）可访问；AUSHARE 网站访问返回 404 |
| WEB-002 | 提供查询接口：返回指定日期各桌各小时的占用情况；响应中不含其他用户的姓名、电话、邮箱等个人信息；默认允许匿名查看，后台可配置为"登录后才能查看"（CFG-005） |
| WEB-003 | 页面网格中，已占用时段置灰；处于"待付押金"锁定中的时段同样视为占用 |
| WEB-004 | 提交预约时，服务端重新校验营业时间、粒度、冲突、时长限制；不信任前端传入的价格、押金、状态 |
| WEB-005 | 冲突时返回明确提示（"This time slot has just been taken. Please choose another."），并说明待付押金的保留会自动释放（"Slots awaiting a deposit are released automatically if not paid within N minutes."，N 为锁定时长）；不创建任何记录。冲突时段是当前顾客自己保留中的预约时，改为提示 "You already hold this time slot (<编号>, awaiting deposit)."（2026-11-07 验收后修改） |
| WEB-006 | 创建预约需要登录；未登录用户跳转到登录页，登录后回到原选择 |
| WEB-007 | 所有时间按公司时区 `Australia/Adelaide` 显示和计算，数据库存 UTC；必须覆盖夏令时切换日，以及周五、周六跨午夜时段（周六夜至周日凌晨 2 点）的占用判断、冲突检测和过期释放 |
| WEB-008 | 页面展示每个时段的价格和应付押金，数值与服务端计算（BK-009）一致 |
| WEB-009 | 提交预约时，若当前时间距开始时间已不足"免费取消提前时长"，支付页须显著提示"This booking cannot be cancelled free of charge."；预约记录保存该事实（创建时是否已在取消窗口内）。确认页只在预约仍为待付押金或已确认时显示这条提示；预约一旦取消、过期、未到场或已完成，不再显示，避免和取消成功的提示同屏矛盾（2026-11-14 验收时发现并修正） |
| WEB-010 | 跨午夜时段的预约，起止时间显示、押金计算、邮件和确认页文案均正确（如"Fri 6 Nov, 11:00 PM – Sat 7 Nov, 1:00 AM"） |

## E. 权限与隔离（SEC / ISO）

| 编号 | 需求 |
|---|---|
| SEC-001 | 新增用户组：球厅员工（查看和操作全部预约）、球厅管理员（含配置与桌台管理权限） |
| SEC-002 | 门户用户只能读取自己名下的预约，不能读写他人预约 |
| SEC-003 | 记录规则按 `website_id` 过滤，AUSHARE 网站用户读不到任何预约数据 |
| ISO-001 | 模块安装后，AUSHARE 网站原有页面、产品、邮件模板行为不变（回归测试：安装前后对比） |
| ISO-002 | 模块不修改 Odoo 核心模型的通用逻辑；对核心模型的扩展只增加字段或带条件的行为，且只对本模块的预约生效 |

## F. 已确认、留待阶段 4 实现的规则（本阶段不实现，仅预留字段）

| 编号 | 规则 |
|---|---|
| RF-001 | 免费取消：开始前 ≥ 取消窗口（快照值，默认 24 小时）取消，全额退押金 |
| RF-002 | 取消窗口内取消：押金不退。开始前不足取消窗口时才下的预约同样适用，支付页须按 WEB-009 提示 |
| NS-001 | 未到场：预约开始时间 + 等待时长（快照值，默认 30 分钟）后仍未标记"已到店"，系统将状态置为"未到场"，押金没收 |
| NS-002 | 员工可在等待时长内手动标记"已到店"；超时后如需恢复，须管理员操作并记录原因 |
| ST-001 | 现场结算：员工录入实际台费 → 扣除已付押金 → 余额以 EFTPOS 或现金收取 → 预约变"已完成" |
| ST-002 | 押金退款记录退款原因和操作员 |
| ST-003 | 每日对账报表：当天收取押金、已退款、已抵扣、未到场没收 |
| ST-004 | 押金的 GST 处理待会计确认后再设计。阶段 4 前不实现；押金产品税率保持后台可配置，代码中不得写死税率或含税/不含税口径 |

## H. 已确认的决定（来自 2026-11-04）

1. 临近开始才预约：允许，支付页明确提示不可免费取消（WEB-009）
2. 跨午夜营业：支持，时段归属开始日（TBL-004、BK-002）
3. 匿名查看占用网格：默认允许，后台可配置为需登录（WEB-002、CFG-005）
4. GST：暂不处理，会计确认后再设计（ST-004）
5. 最长连续预约 4 小时、最多提前 14 天，均可配置（CFG-001）
6. 开发采用迭代方式，每个阶段结束都有可演示成果；新增后台界面与演示环境规格（第 J 节，2026-11-04 确认）
7. 界面语言为英语（顾客主要是澳洲本地客户）；网站、后台、提示信息均用英语原文，提示用 `_()` 包裹以便将来加中文翻译（2026-11-05 确认；WEB-005、WEB-009、WEB-010、ADM-003 的示例文字已相应改为英文）

8. 预约编号允许跳号（序列号不随事务回滚，校验失败的保存也会消耗编号），不使用无间隔编号；发票类连续编号在阶段 4 由会计模块处理（2026-11-05 确认）
9. 阶段 2 不含支付，仅用于演示，阶段 4 接入 Stripe 后才上线；网上预约提交后发 "Booking received – awaiting deposit" 邮件；顾客 "My Bookings" 列表放到阶段 4；TBL-006 示例文字改为英文（2026-11-06 确认，见 `docs/demo/phase-2.md`）

10. 后台预约表单按营业日选时间，Business Date 为营业日；Start Time 按 6:00 AM … 11:00 PM、12:00 AM (next day) … 5:00 AM (next day) 排列；网格及最多提前天数的“今天”均按营业日计算（2026-11-06，替代 `docs/design/1.3-booking-model.md` 第九节第 2 条“按日历日”）

# qclub_billiard 需求规格：阶段 3（约球留言板）

放置路径：`docs/spec/phase3.md`　状态：**已定稿（修订版）**（2026-11-09 评审通过：留言板并入预约页，取消昵称；第 H 节原 8 个决定不变，新增第 9、10 条）
每条需求必须有至少一个测试，测试名或 docstring 中带编号（如 `test_brd_004_one_post_per_booking`）。
编号前缀统一为 BRD；第一个编码任务把 BRD 加入 `tools/make_report.py` 的覆盖检查。
界面文字为英语（规格 H.7），示例文字以本文件为准。

**一句话**：有已确认预约的顾客，在自己的预约时段下发帖找球友；其他顾客回复或申请加入，发帖人决定接受谁。留言板只是"找人一起打"，不涉及分摊费用（AGENTS.md 第 10 节：不做多人分别支付，也不做独立论坛）。

**留言板没有独立页面**：帖子挂在预约时段上，全部在预约页 `/billiard/booking` 内查看和操作，用户不离开预约页。

## A. 显示名与隐私

| 编号 | 需求 |
|---|---|
| BRD-001 | 留言区不使用昵称，显示名由服务端统一决定：**未登录的访问者**看到所有人都显示 "Q Club Player"；**已登录的顾客**看到对方的姓名（`res.partner` 的 Name，顾客在 My Account 的 Edit information 修改）。不修改 `res.partner` |
| BRD-002 | 姓名为空，或是邮箱 / 电话形式（含 `@`，或数字 7 位及以上）时，对任何人都显示 "Q Club Player" |
| BRD-003 | 预约页上的留言板内容、接口响应（包括帖子摘要接口）、邮件中，绝不出现其他顾客的电话、邮箱、登录账号或预约编号；未登录访问者的页面和接口响应中不得出现任何顾客的姓名 |

## B. 发帖

| 编号 | 需求 |
|---|---|
| BRD-004 | 只有预约本人、且预约为"已确认"状态、且开始时间在未来时才能发帖；每条预约最多一个帖子（数据库唯一约束） |
| BRD-005 | 帖子内容：纯文本消息（1–500 字符）、技术水平（Any / Beginner / Intermediate / Advanced）、需要的球友人数（1 到"每帖最多球友数"，默认上限 3）。时段、桌台名称和类型取自预约，不接受前端传值 |
| BRD-006 | 入口：顾客点击网格上自己已确认预约的格子，帖子面板显示 "Find players" 并在面板内发帖；预约确认页在状态为已确认时也显示 "Find players"，链接到预约页的对应日期并自动打开面板 |

## C. 查看

| 编号 | 需求 |
|---|---|
| BRD-007 | 预约网格上，有开放帖子的预约所占的每一格显示标记和剩余名额（如 "Join · 2"）；网格下方列出当前营业日开放的帖子（"Players wanted on Fri 13 Nov"），随日期切换，点击一条与点击对应格子效果相同。时间按 Australia/Adelaide 显示，跨午夜格式与 WEB-010 相同 |
| BRD-008 | 点击带标记的格子，在预约页内（网格下方，位置同 "Selected booking"）打开帖子面板，不跳转页面，并滚动到可见位置：发帖人显示名、时段、桌台、技术水平、消息、剩余名额、回复、已接受球友的显示名（均按 BRD-001）。没有开放帖子的占用格仍不可点击（WEB-003 不变）；支持带帖子编号的预约页地址，打开对应日期并展开面板（用于邮件和登录后返回） |
| BRD-009 | 默认未登录可以看；后台开关 "Login Required to View Board"，默认关闭，开启后未登录用户看不到帖子摘要和面板（网格占用不受影响，仍由 CFG-005 控制）。未登录用户不能发帖、回复、申请、举报，点击时跳转登录并返回预约页和原帖子 |

## D. 回复与申请加入

| 编号 | 需求 |
|---|---|
| BRD-010 | 已登录的顾客可在开放的帖子下回复（纯文本 1–500 字符）；帖子关闭后不能再回复。帖子、回复和申请都显示发布时间（球馆时区），被隐藏的回复不显示（2026-11-10 验收时确认） |
| BRD-011 | 顾客可申请加入开放的帖子，附一句可选留言；发帖人不能申请自己的帖子；同一顾客对同一帖子最多一个有效申请（数据库部分唯一约束） |
| BRD-012 | 发帖人可接受或拒绝申请；申请人可在开始前撤回；发帖人可在开始前移除已接受的球友 |
| BRD-013 | 已接受人数不得超过需要的人数；并发接受时恰好不超额（真实 PostgreSQL 事务测试，不 mock）。名额满后不能再申请 |
| BRD-014 | 申请加入不创建预约、不改变预约的时段或金额、不产生任何费用；线下由发帖人和球友在预约时段到店碰面 |

## E. 帖子关闭

| 编号 | 需求 |
|---|---|
| BRD-015 | 预约变为已取消、已过期或未到场时，帖子立即自动关闭；与预约状态变更在同一事务中完成 |
| BRD-016 | 到达预约开始时间后帖子自动关闭（读取时按时间判断，不依赖定时任务）；关闭的帖子不再显示标记、不在当日列表中；通过带帖子编号的地址打开时，面板只读并显示 "This post is closed." |
| BRD-017 | 员工修改预约时段或桌台时，帖子显示随预约更新；已接受的球友收到时段变更通知 |

## F. 通知

| 编号 | 需求 |
|---|---|
| BRD-018 | 邮件通知：发帖人收到新申请；申请人收到接受、拒绝或被移除；已接受的球友收到帖子关闭或时段变更。回复不发邮件 |
| BRD-019 | 通知使用 Q Club 版式、发件人和网站域名（同 2.2、穿刺 2）；发件人未设置时不发；收件人是已登录顾客，显示名按已登录规则，不含其他顾客的联系方式；发送失败不影响操作本身 |

## G. 管理与安全

| 编号 | 需求 |
|---|---|
| BRD-020 | 已登录顾客可举报帖子或回复（原因：Spam / Abuse / Personal information / Other，可附说明）；同一顾客对同一内容只能举报一次 |
| BRD-021 | 后台 **Board** 菜单：帖子、回复、举报队列；员工可标记举报已处理、隐藏或恢复内容，并记录操作人和时间。不做物理删除 |
| BRD-022 | 被隐藏的内容对顾客不可见，但后台保留原文。隐藏帖子只隐藏留言文字：顾客看到 "This post was removed."，格子上的 Join 标记、Apply to join、回复和已有申请都继续可用（2026-11-10 验收时确认）；隐藏回复显示 "This reply was removed."。当天没有可显示的帖子时，留言区显示一行 "No one is looking for players on <日期> yet."（2026-11-10 验收时确认） |
| BRD-023 | 管理员可按网站封禁顾客（原因、可选到期时间）；被封禁者可浏览，但不能发帖、回复、申请、举报；封禁不影响其预约 |
| BRD-024 | 发帖、回复、申请、举报都有频率限制（默认每分钟每人 5 次，后台可配），超限提示 "You're doing that too often. Please try again shortly." |
| BRD-025 | 所有用户内容按纯文本存储和显示：不渲染 HTML、不把网址转为链接，防 XSS（覆盖帖子、回复、申请留言、举报说明、姓名、邮件） |
| BRD-026 | 所有写操作由服务端校验身份、状态和归属；门户用户不能直接通过 ORM/RPC 读写留言板模型，写操作只经路由完成；CSRF 校验 |
| BRD-027 | 所有留言板模型带 `website_id` 和记录规则；不提供独立的留言板页面或网站菜单；AUSHARE 上所有留言板路由返回 404，预约页接口不返回帖子数据；`make iso-check` 无差异；不继承 `res.partner` 等核心模型 |
| BRD-028 | 新配置项按网站保存：开关 Online Board、Login Required to View Board、每帖最多球友数、频率限制；数值校验；仅管理员可改 |
| BRD-029 | 留言板首次发帖、回复或申请前须勾选同意社区须知（内容见问题 7）；记录同意时间 |

## G2. 我的账户与日期提示（2026-11-10 验收时新增并确认）

| 编号 | 需求 |
|---|---|
| BRD-030 | My Account（`/my`）显示 "My Bookings & Players" 卡片，只在开启 Online Booking 的网站显示；其他网站的页面输出不变，`/my/billiard` 返回 404 |
| BRD-031 | `/my/billiard` 集中显示当前顾客的预约、自己的帖子（含待处理申请数）、自己发起的申请及状态、相关回复；四类内容分标签页显示并带数量，地址记住当前标签（2026-11-10 验收时确认） |
| BRD-032 | 该页面只显示当前顾客自己的记录；其他顾客只显示姓名，不含联系方式、登录账号和他人预约编号；用户内容按纯文本显示 |
| BRD-033 | 该页面只读，打开不改变任何记录；每条可链接到预约页的对应帖子或预约 |
| BRD-034 | 预约页显示可预约日期的日期条，点击切换日期；当天已有有效预约的日期下显示提示点，所有访问者（含未登录）都能看到，便于找球友；接口只返回日期，不含任何个人信息；开启 CFG-005 时未登录访问者看不到（2026-11-10 验收时确认） |

## H. 已确认的决定（2026-11-09，均按括号内建议）

1. **谁能发帖**：只有**已确认**的预约才能发帖（待付押金的预约 10 分钟内可能过期）。阶段 2–3 里"已确认"要靠员工点 Confirm，阶段 4 起由付押金自动完成。同意吗？（建议：同意）
2. **未登录能否浏览**：默认能看，后台可关（与占用网格一致）。未登录时显示名一律为 Q Club Player（第 10 条）。同意吗？（建议：同意）
3. **球友之间如何联系**：系统不交换电话或邮箱，按预约时段到店碰面；帖子里可以回复沟通。页面提醒 "Don't share personal contact details"，但不做自动过滤。同意吗？（建议：同意）
4. **申请和回复的通知**：发邮件给申请相关的人，回复不发（避免打扰）。同意吗？（建议：同意）
5. **权限划分**：员工可处理举报、隐藏或恢复内容；**只有管理员能封禁顾客**。原草案是员工也能封禁，这里建议收紧。同意吗？（建议：同意）
6. **举报是否自动隐藏**：不自动隐藏，由员工处理（防止恶意举报，初期内容量也小）。同意吗？（建议：同意）
7. **社区须知文字**：需要你提供或确认最终英文内容（可由我起草：友善交流、不发联系方式、到店自负、Q Club 可移除内容）。正式文字是否请法律 / 业务确认？（建议：我起草，你确认；阶段 6 上线前再过一次）
8. **何时关闭**：预约开始时帖子自动关闭，到店后不再能申请。同意吗？（建议：同意）
9. **留言板位置**（2026-11-09 你的决定）：不做独立页面，全部在预约页内：网格格子上的标记、网格下方的帖子面板和当日列表
10. **取消昵称**（2026-11-09 你的决定）：未登录显示 "Q Club Player"，登录后显示姓名。登录顾客之间能看到彼此的姓名，上线前在社区须知中写明

## I. 任务拆分（建议）

| 任务 | 内容 | 规格 |
|---|---|---|
| 3.1 | 显示名规则、配置项 | BRD-001/002/003/028 |
| 3.2 | 帖子模型、网格标记、帖子面板、当日列表、发帖、社区须知、权限与隔离 | BRD-004–009/016/025/026/027/029 |
| 3.3 | 回复、申请、接受、关闭联动、通知 | BRD-010–015/017–019 |
| 3.4 | 举报、后台管理、封禁、频率限制 | BRD-020–024 |

风险最高的是 BRD-013（并发超额）、BRD-015（关闭联动，须改动预约写入）和 BRD-003 / BRD-025（隐私与 XSS）。

## 任务 3.1 可演示部分

本任务只有后台配置，显示名规则由自动测试验证；用户能看到的留言板功能从 3.2 开始。

1. 运行 `make demo`，用管理员登录后台 Billiard Settings → Q Club → **Online Board** 分组：默认人数 3、频率 5；输入 0 无法保存。
2. `demo-staff` 不能修改配置。网站菜单中没有 Board，My Account 页面不变。

## 任务 3.2：步骤 1–6 验收说明

- 演示数据不预置帖子；沿用现有桌台、顾客和 Online Board 配置，由顾客手动发帖。无需修改或重建演示数据脚本。
- 步骤 1：选择未来营业日、空闲桌台和连续两小时，顾客提交后由 `demo-staff` 在后台 Confirm。回到确认页点击 **Find players**，应带日期和 booking 参数回到预约页并展开表单；也可点网格上的 **Yours**。预约已开始、未确认、已有帖子或关闭 Online Board 时，确认页无此入口。
- 步骤 2：另建待付押金预约，点 **Yours**，只显示确认提示，不能发帖。没有帖子且不属于本人的占用格仍带 aria-disabled，不能点击。
- 步骤 3：首次发帖显示完整 Community Guidelines，必须勾选同意。之后同一网站无需再次同意；切换网站不会沿用同意记录。
- 步骤 4：输入消息、Intermediate、2 人，提交后不跳页；占用的每小时都有标记，当日列表出现帖子。点任一标记或列表按钮打开同一帖子；键盘 Tab、Enter、空格可操作。选空闲格时帖子面板关闭，恢复 Selected booking。
- 步骤 5：无痕窗口打开相同日期及 post 参数，显示 Q Club Player；点击 **Apply to join** 或回复框，登录后返回原日期和帖子，显示服务端决定的姓名，并可回复或申请。开启 Login Required to View Board 后，无痕窗口只能看到登录入口，预约网格仍独立受 CFG-005 控制。
- 步骤 6：检查无帖占用格不可点、AUSHARE 页面和三个 board/post/post/create 接口均为 404。把消息设为 `<script>alert(1)</script>` 和网址，应显示原文、无弹窗、无链接。取消预约或到开始时间后，刷新后无标记／列表项；用 post 地址仍能看到只读内容和 **This post is closed.**

本次 Codex 沙箱的 `make test`、`make lint` 因 Docker socket 权限被拒绝而未运行；`make demo`、`make e2e`、`make iso-check` 和上述桌面／手机人工演示待独立验证，不能视为通过。未生成 docs/reports。

## 任务 3.3：步骤 5、7–11、14 验收说明

- 无需预置回复或申请，也无需修改演示数据脚本；使用现有 A、B、C 账号和步骤 1–4 新建的未来已确认预约。每轮演示重新建帖，避免上次的申请终态影响结果。
- 步骤 5：未登录点 **Apply to join** 或回复框后登录，返回同一日期及帖子。匿名回复和已接受名单均显示 Q Club Player。
- 步骤 7：B 首次回复须勾选 Community Guidelines；消息 1–500 字符。脚本及网址显示原文，不执行、不转链接。回复不可编辑或删除，也不发邮件。
- 步骤 8：B 附可选留言（最多 200 字符）申请；只向 A 展示申请列表，B 只看到自己的申请，其他顾客看不到申请留言。A 收到新申请邮件。
- 步骤 9：A 可 Accept / Decline，接受后可 Remove；B 开始前可 Withdraw，撤回后可重新申请，拒绝或移除后不能再申请。接受 B、C 后显示 **Full**，不能继续申请。接受、拒绝、移除均通知申请人；撤回不通知。
- 步骤 10：核对预约数量、时段、台费、押金和状态均未因申请或回复改变，不收取额外费用。
- 步骤 11：员工修改开始时间、时长或桌台，重新打开对应新日期后标记、面板更新；只向已接受球友发变更邮件。邮件使用网站域名的 date/post 链接，不含其他顾客联系方式或预约编号。
- 步骤 14：取消、过期或未到场立即关闭帖子，同事务回滚；已接受球友收到关闭邮件。到开始时间自然只读不发通知。无帖子预约行为保持原样。Q Club 发件人未配置不发邮件；排队失败仅记日志。

本次沙箱 `make test`、`make lint` 均因 Docker socket 权限拒绝而未执行；桌面／手机 e2e、邮件、`make demo` 与上述人工流程待有 Docker 的环境验证，不能视为通过。按任务要求未生成 docs/reports。

## 页面草图（文字描述，设计时细化）

留言板全部在预约页 `/billiard/booking` 内，不跳转页面：

- **网格**：有开放帖子的预约，占用的每一格在 "Booked" 外显示标记（如 "Join · 2"）；普通占用格仍灰色不可点
- **帖子面板**（网格下方，位置同 "Selected booking"）：显示名（未登录为 Q Club Player，登录后为姓名）、时段、桌台、技术水平、消息、剩余名额、**Apply to join**、已接受的球友、回复和回复框；每条内容旁有 Report
- **当日列表**（面板下方）："Players wanted on Fri 13 Nov"，随日期切换，点一条等于点对应格子
- **发帖人视角**：点自己已确认预约的格子，面板显示 **Find players**；发帖后面板多一个申请列表，每条有 Accept / Decline，已接受的可 Remove
- **后台 Board 菜单**：Posts、Replies、Reports、Banned Customers

## 3.5 My Account 与日期提示（BRD-030–034）

复用现有演示预约、帖子、申请及回复，无需新增演示数据。先运行 `make demo` 升级模块；本次沙箱无法访问 Docker，以下步骤仍需人工在演示环境验收。

1. 在 Q Club 登录顾客账号，打开 `/my`，点击 **My Bookings & Players**。
2. 核对 **My bookings** 的本人预约编号、时段、桌台、状态，未来预约在前；点击编号打开确认页，再返回账户页。
3. 对未来已确认、未发帖的预约点击 **Find players**，确认打开对应日期的发帖面板。发布后返回账户页，从 **My posts** 点击该时段，应打开对应帖子。核对接受人数、需要人数、待处理申请数。
4. 用另一顾客申请并回复该帖子，分别查看双方 **My join requests**、**Messages**；操作仍在预约页帖子面板完成。检查没有别人的预约编号、邮箱、电话或登录账号，HTML 文本不能执行。
5. 打开预约页，日期框上方应有从最小到最大日期的全部日期按钮；点击切换日期，日期框同步。直接修改日期框，按钮选中状态同步。
6. 当天已有有效预约的日期下有提示点，登录和未登录都能看到；已取消的预约不产生点。手机上左右滑动日期条并真实点击，重复检查账户页链接。
7. 切到 AUSHARE 的 `/my`，确认没有此卡片或链接；访问 `/my/billiard` 返回 404。Q Club 退出后访问此地址，应登录并返回账户页。
8. 查看账户页前后核对预约、帖子、申请及回复未改变。阻断 reminders 请求后，日期按钮和预约网格仍可正常使用。

# 任务 4.1 设计说明：Stripe 押金穿刺与 12 张桌子的演示数据

状态：**待你审阅**（2026-11-11；因两家公司的决定改为任务 4.1，排在 4.0 多公司之后）
对应规格：`docs/spec/phase4.md` PAY-012，第 H 节第 1、3 条；穿刺 3（`docs/progress.md` 第七节）

## 一、要回答的问题

1. Odoo 19 自带的 Stripe 支付能否只收押金、关联到预约，并在付款成功后由服务端确认？
2. 支付方式能否只对 Q Club 网站生效，AUSHARE 的结账页完全不变？
3. 付款成功后，Odoo 会不会自动生成会计凭证？
4. 退款能否通过 Odoo 原路退回？
5. Stripe 的付款通知能否送到 WSL 里的演示环境？

## 二、读源码已经确认的情况

以下来自测试镜像中的 Odoo 19 源码，穿刺时再用真实的测试付款验证一遍。

| 问题 | 结论 | 依据 |
|---|---|---|
| 按网站限定 | **可以**。支付方式设置了网站，就只在该网站显示 | `website_payment` 的 `_get_compatible_providers` 只保留"未设网站或网站相同"的支付方式 |
| 自动生成会计凭证 | **会**。每笔成功付款（包括退款）都会在支付方式的日记账里生成并过账一笔付款凭证 | `account_payment` 的 `_post_process`：交易成功且不是验证交易时调用 `_create_payment()` |
| 退款 | **支持**。原路退回 Stripe，Odoo 生成一条退款交易并接收 Stripe 的退款通知 | `payment_stripe` 的 `_send_refund_request` |
| 付款通知 | Odoo 提供 `/payment/stripe/webhook`，并用支付方式里保存的签名密钥校验 | `payment_stripe` 的控制器 |
| 金额由谁决定 | Odoo 通用的付款接口金额来自浏览器（用令牌防篡改）。本模块会像发票、销售订单那样，**在服务端按预约押金创建交易**，浏览器不能决定金额 | `payment` 的 `/payment/transaction` |

另外，`payment_stripe` 模块目前**未安装**。安装它是在共用数据库里装一个 Odoo 自带模块，会新增一个默认停用的 Stripe 支付方式，AUSHARE 页面不会因此变化。穿刺会用 `make iso-check` 确认这一点。

## 三、需要你决定：自动生成的会计凭证怎么处理

第 H 节第 3 条已定"本阶段不在账簿里生成会计凭证；如果 Odoo 会自动生成，先停下来请你确认"。源码确认会自动生成，所以有两个做法：

| 做法 | 效果 | 风险 |
|---|---|---|
| **A. 不生成凭证（建议）** | 本模块对"关联 Q Club 预约的交易"跳过自动生成付款凭证；资金流水只记在本模块和 Stripe 控制台。AUSHARE 和其他交易的行为不变 | 以后接入会计时，要把这段时间的 Stripe 收款补记进账簿（日对账报表和 Stripe 导出都能提供明细） |
| B. 生成凭证，用 Q Club 专用日记账 | 每笔押金和退款都记进共用公司的账簿，单独一个 "Q Club Stripe" 日记账 | 和 AUSHARE 共用应收和科目，会计口径（GST、没收）还没定，记进去的凭证以后可能要冲销重做 |

如果 Stripe 支付方式一定要绑定日记账，做法 A 也要新建一个 "Q Club Stripe" 日记账，但里面不会有凭证。穿刺会确认是否必须绑定。
**两家公司后（第 H 节第 10 条）**：Stripe 支付方式和日记账都建在 TAB Entertainment 下，做法 B 的凭证也只会记进 TAB Entertainment 的账，不再影响 AUSHAREU。但 GST 口径还没和会计确认，仍建议本阶段用做法 A。

## 四、穿刺怎么做

全部在演示库 `qclub_demo` 中进行，只用测试密钥和 Stripe 测试卡。

1. 在演示库安装 `payment_stripe`，运行 `make iso-check`，确认 AUSHARE 无差异。
2. 用一个仓库外的脚本，从 `~/.config/qclub/stripe-test.env` 读取测试密钥，写入 Stripe 支付方式（测试状态，限定 Q Club 网站）。脚本检查密钥是 `_test_`，不打印密钥。
3. 用 Stripe 官方命令行工具的 Docker 镜像 `stripe/stripe-cli` 转发付款通知：`stripe listen --forward-to http://localhost:8069/payment/stripe/webhook`，密钥同样从文件读取。镜像固定一个至少发布两周的版本，约 18.5 MB，**下载需要你同意**。
4. 在穿刺分支上写一个最小原型：为一条待付押金的预约在服务端创建交易，金额等于押金，用 4242 测试卡在浏览器里付款。逐项记录：
   - 付款通知是否到达，交易是否变为完成，原型能否把预约改为已确认；
   - 是否生成了会计凭证，做法 A 能否干净地跳过；
   - 退款能否原路退回，退款通知是否到达；
   - 被拒绝的卡（4000 0000 0000 0002）和 3D Secure 卡（4000 0025 0000 3155）的表现；
   - 支付方式是否必须绑定日记账；
   - AUSHARE 结账页是否看不到 Stripe。
5. 结果写入 `docs/spikes/03-stripe-deposit.md`。**原型代码不合并**，正式代码在任务 4.2 由 Codex 按设计编写。如果穿刺推翻了规格里的某条，先改规格再继续。

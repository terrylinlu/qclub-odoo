# 修复设计：task-4.6-v2-01 — Daily Reconciliation 向导缺少显示名称

## 问题

验收 phase 4 demo 第 1-14 步全部通过后，owner 在 Daily Reconciliation 页面点击工具栏 "New" 按钮（打开一个新的空白向导，便于不离开当前页就核对另一个日期），面包屑标题显示为：

```
qclub.reconciliation,NewId_0x7a8b58e24700
```

而不是正常的人类可读文字。

## 根因

`qclub.reconciliation`（`addons/qclub_billiard/models/reconciliation.py`）是一个 `TransientModel`，没有定义任何名称类字段，也没有 `_rec_name` 或 `display_name` 的 override。Odoo 在没有名称字段时，`display_name` 的最终兜底是 `"%s,%s" % (self._name, self.id)`；对尚未保存的新记录，`self.id` 是内部 `NewId` 对象，其 repr 形如 `NewId_0x...`，于是拼出了这个技术字符串，并被面包屑直接显示出来（面包屑只在 `display_name` 为空时才退化显示 "New"）。

这纯粹是显示问题：表单本身功能、数据计算都正常；只是标题难看、让员工困惑。

## 修复方案

给 `qclub.reconciliation` 增加一个 computed 的 `display_name`（override `_compute_display_name`，或者更简单地加一个 `name` 字段 + `_rec_name = 'name'`），固定返回 `_("Daily Reconciliation")`（不需要随 website/date 变化，因为这不是可检索的持久化记录列表，一个固定的人类可读标题就够了）。

这样：
- 面包屑在新建/已有的向导上都会显示 "Daily Reconciliation"，不再出现技术字符串。
- 工具栏 "New" 按钮的行为不变，继续保留（员工用它另开一个向导核对别的日期，无需回到菜单重新点）。

## 测试计划

- 新增一个 HTTP 或普通单元测试：创建一个 `qclub.reconciliation` 记录（含未保存的 new 记录），断言 `display_name` / `name` 等于 "Daily Reconciliation"，不包含 "NewId" 或模型技术名。
- `make lint test iso-check` 全绿。

# 任务 4.0 设计说明：两家公司（TAB Entertainment 与 AUSHAREU）

状态：**已批准**（2026-11-11，第六节三项均同意）
对应规格：`docs/spec/phase4.md` 第 J 节 CO-001 至 CO-006，第 H 节第 10、11 条

## 一、目标

Q Club 网站改为属于 TAB Entertainment Pty Ltd，AUSHARE 仍属于 AUSHAREU PTY LTD；网站结构不变，顾客一个账号通用两个网站，My Account 按网站区分。先穿刺弄清 Odoo 19 多公司规则对现有功能的影响，再补上模块里的按公司隔离，最后整理生产迁移清单。

## 二、已知情况

- 模块代码只在一处用到公司：通过网站所属公司取币种（AUD）。两家公司都用 AUD，不受影响。
- 预约编号序列不属于任何公司，两家公司可以共用。
- 生产库已有 3 家公司（AUSHAREU 和两家演示公司），已装 `payment_stripe`（未启用）。新增公司不需要安装新模块。
- 测试基础库由 `docker/seed_websites.py` 建两个网站，目前都属于默认公司；演示库在其上由 `docker/demo_data.py` 补数据。

## 三、穿刺：要验证的问题

## 四、穿刺之后的实现（由 Codex 编写，单独 PR 请你验收）

- **按公司隔离**：本模块所有模型的后台访问加多公司记录规则，按网站所属公司限制（CO-002）。门户顾客走现有路由，不受影响。
- **My Account**：按穿刺第 3 项的结论，Q Club 的 My Account 不显示 AUSHARE 的订单和发票卡片；AUSHARE 侧保持不显示 Q Club 内容（CO-004）。如果做这件事需要改 AUSHARE 页面的输出，先停下来请你确认（AGENTS.md 红线 7）。
- **测试环境**（需要你批准修改 `docker/`）：
  - `docker/seed_websites.py` 新建 TAB Entertainment，把 Q Club 测试网站挂过去。测试中只用占位的 ABN 和地址；
  - `docker/demo_data.py` 让员工账号能访问 TAB Entertainment，演示账号覆盖两个方向的跨网站登录；
  - 测试和演示库暂不安装澳洲科目表。阶段 4 不生成会计凭证，用不到；生产上的科目表和 GST 由你和会计配置。
- **测试**：新增 CO-001 至 CO-006 的测试，把 CO 加入 `tools/make_report.py` 的覆盖检查；已有测试如果因多公司需要修改，先列出来请你批准。
- **生产迁移清单** `docs/deploy/company-split.md`：新建公司（名称、ABN、地址、AUD、澳洲科目表和 GST）、把 Q Club 网站改到新公司、给员工分配公司权限、迁移后检查 AUSHARE 页面和指纹。先在 `qclub_prodcopy` 演练；生产上由你执行，我不操作生产。

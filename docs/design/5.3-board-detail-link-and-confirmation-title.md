# 任务 5.3 设计：看板详情入口 + 预约确认页标题按状态显示

规格：`docs/spec/phase5.md` RT-010（新增）。另修一个验收中发现的 bug（预约确认页标题），不是新需求编号，按缺陷处理。

## 一、Bug：预约确认页标题写死 "Booking received"

`addons/qclub_billiard/views/booking_templates.xml` 的 `booking_confirmation` 模板（约第 60 行）`<h1>Booking received</h1>` 是写死的，不管预约当前是什么状态。取消/过期/没收后跳转到这个页面，标题还是显示"Booking received"，跟下面显示的实际状态（比如 Cancelled）矛盾。

改成按 `booking.state` 显示对应标题：

| state | 标题 |
|---|---|
| pending | Booking received |
| confirmed / arrived | Booking confirmed |
| done | Booking completed |
| cancelled | Booking cancelled |
| expired / no_show | Booking expired |

用 `t-if`/`t-elif` 链或者一个 dict 查表都可以，保持模板风格跟文件里其他地方一致。页面其余内容（预约编号、桌台、时段、费用等）不变。

补一个测试：对这几种 state 分别渲染确认页，断言 `<h1>` 文本符合上表。

## 二、RT-010：看板加查看入口

`table_board.js` 的 `TableBoard` 组件新增 `useService("action")`，占用卡片和"当天剩余安排"列表的每一项都变成可点击：

```js
openBooking(id) {
    this.action.doAction({
        type: "ir.actions.act_window", res_model: "qclub.booking", res_id: id,
        views: [[false, "form"]], target: "current",
    });
}
```

`target: "current"` 让它作为 Table Board 的下一级面包屑打开，用户点浏览器后退或者点面包屑上的 "Table Board" 都能回到看板（Odoo 自己的面包屑栈机制，不用自己写返回逻辑）。看板本身的 state（已加载的 tables 数据）组件卸载后会丢失，重新进来会走 `onMounted` 的初次 RPC 重新加载，这是预期行为，不算 bug。

后端 `get_table_board` 的 `upcoming` 列表现在要带上 `id`（之前只有 `start`/`end`），仅用于前端生成链接，模板里不展示这个字段本身（不展示预约编号/顾客姓名，维持 RT-003 的最小信息暴露原则，只是多了一个可点击目标）。

权限不用额外处理：能看到 Table Board 的员工本来就在 `group_billiard_staff`/`group_billiard_manager`，对 `qclub.booking` 有读权限（沿用现有 ACL），点进去不会出现权限不足的情况。

测试：
- `get_table_board` 的 `upcoming` 列表每项含 `id`（断言，不是新增需求编号，归入现有 RT-003 的测试补充）。
- 前端契约测试（`tools/test_realtime_frontend.mjs`）加一个用例：点击卡片/列表项会调用 `action.doAction`，参数是对应预约的 `res_id` 和 `target: "current"`。

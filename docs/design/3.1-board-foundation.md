## 二、数据模型：`qclub.board.profile`（新）

| 字段 | 说明 |
|---|---|
| `website_id` | 必填，所属网站 |
| `partner_id` | 必填，顾客；`ondelete="restrict"` |
| `nickname` | 必填，保存时去掉首尾空格，连续空格合并为一个 |
| `active` | 默认 True（预留，本任务不提供停用入口） |

约束（数据库层）：

- `UNIQUE(website_id, partner_id)`：每位顾客在每个网站一条
- `models.UniqueIndex("(website_id, lower(nickname))")`：同一网站内昵称不区分大小写唯一（已在 Odoo 19 源码中确认该写法可用）

不修改、不继承 `res.partner`（ISO-002、BRD-001）。

## 三、昵称校验（BRD-002）

全部在模型的 Python 约束中，路由不重复实现：

| 规则 | 英文提示 |
|---|---|
| 去空格后 2–20 个字符 | Nickname must be 2 to 20 characters. |
| 只允许字母、数字、空格、下划线、连字符（ASCII） | Nickname can only contain letters, numbers, spaces, underscores and hyphens. |
| 不能是邮箱或电话形式（含 `@`，或数字占 7 位及以上） | Nickname cannot be an email address or phone number. |
| 不含保留词 `admin`、`staff`、`qclub`（不区分大小写，子串匹配） | This nickname is not allowed. |
| 已被占用（捕获数据库唯一冲突） | This nickname is already taken. |

说明：只允许 ASCII 是为了防止用外观相同的字符冒充别人（规格 BRD-002 写的是"字母"，见第九节问题 1）。

## 四、对外输出（BRD-003）

`qclub.board.profile` 提供 `_public_data()`，只返回 `{"nickname": ...}`。后续帖子、回复的接口和模板只能经它取发帖人信息。测试检查接口响应和页面里没有测试顾客的姓名、电话、邮箱。

## 五、配置项（BRD-028，加到 `qclub.config`）

| 字段 | 默认 | 校验 |
|---|---|---|
| `online_board`（Online Board） | False | — |
| `board_requires_login`（Login Required to View Board） | False | — |
| `board_max_players`（Max Players per Post） | 3 | ≥ 1 |
| `board_rate_limit`（Board Actions per Minute） | 5 | ≥ 1 |

Python 约束 + 数据库 CHECK，与现有配置项做法相同；沿用现有权限（只有管理员能改）。后台 Settings 新增 "Online Board" 分组。

## 六、路由

| 路由 | 类型 | 权限 | 作用 |
|---|---|---|---|
| `/billiard/booking/nickname` | http GET | 登录用户（未登录跳转登录并返回） | 设置 / 修改昵称表单 |
| `/billiard/booking/nickname` | http POST | 登录用户，CSRF | 保存昵称；校验错误在表单显示；可选 `next` 参数只接受本站相对路径，防开放重定向，默认回到 `/billiard/booking` |

- 未开启 `online_board` 的网站（包括 AUSHARE）所有路由返回 404，沿用 `_website_config()` 的做法
- 页面用 QWeb 模板，文字自动转义；视图关联到本模块模型（ISO-001 白名单要求，与 `booking_page` 相同）

## 七、权限与隔离（BRD-026、BRD-027）

| 角色 | `qclub.board.profile` |
|---|---|
| 公开 / 门户 | **无任何模型权限**，只经路由，路由校验身份后用 `sudo()` 操作，且只操作当前顾客自己的记录 |
| Billiard Staff | 只读 |
| Billiard Manager | 读、写（用于修改不当昵称），不可删除 |

- 记录规则：门户组 `[('website_id', '=', website.id), ('partner_id', '=', user.partner_id.id)]`（AGENTS.md 要求所有业务模型配记录规则；当前门户没有访问权限，规则作为第二道防线）
- 后台 Board 菜单在 3.4 增加；本任务不加后台菜单，经 Settings 配置

# 任务 4.4 设计：未到场与没收（NS-001–005）

状态：**已批准**（2026-11-16，两点确认均按建议：去掉手动 No-show 按钮改为管理员撤销；未到场通知邮件电话预约也发，文案不提押金）

## 现状（早期阶段遗留的占位代码）

`qclub_booking.py` 已有 `state` 里的 `arrived`/`no_show`，以及两个未加任何校验的占位方法：

```python
def action_arrive(self):
    return self.write({"state": "arrived"})

def action_no_show(self):
    return self.write({"state": "no_show"})
```

表单上也有一个员工可见的手动 **No-show** 按钮。这些都是早期阶段留的占位，4.4 要把它们按规格重做。

## 设计

### 1. 自动没收（NS-001、NS-003）

新增每分钟跑一次的 cron（`qclub_booking_cron_no_show`，与现有 `_cron_expire_pending` 同一个文件/同样的写法）：

```python
@api.model
def _cron_mark_no_show(self):
    bookings = self.sudo().search([("state", "=", "confirmed")])
    now = fields.Datetime.now()
    due = bookings.filtered(lambda b: b.start + timedelta(minutes=b.no_show_wait_minutes) <= now)
    for booking in due:
        with self.env.cr.savepoint():
            booking._mark_no_show()
```

边界：`start + no_show_wait_minutes <= now()` 时没收（即"等待时长结束"那一刻就算，不用再等下一分钟），用快照字段 `no_show_wait_minutes`，不用配置的当前值。

`_mark_no_show()`：
- `state` → `no_show`
- 若 `deposit_state == 'paid'`：`deposit_state` → `forfeited`，记录 `no_show_at = now()`（新字段，等同已付押金没收发生的时间；`paid_amount` 本身就是没收金额，不用新开一个没收金额字段，跟 4.3 取消没收的做法一致）
- 若 `deposit_state == 'no_deposit'`（电话预约，H.5）：只改 `state`，不碰押金字段，`no_show_at` 仍记录（方便对账报表统一按这个时间戳取"未到场发生时间"，ST-009 要用）
- 发邮件（见第 3 节）

### 2. 到店标记窗口（NS-002、NS-005）

`action_arrive` 加时间窗校验：

```python
def action_arrive(self):
    now = fields.Datetime.now()
    for booking in self:
        if booking.state != 'confirmed':
            raise UserError(...)
        if not (booking.start - timedelta(minutes=30) <= now < booking.start + timedelta(minutes=booking.no_show_wait_minutes)):
            raise UserError(_('Can only mark arrived between 30 minutes before the start time and the no-show cutoff.'))
    return self.write({'state': 'arrived'})
```

边界：窗口左端 `>=`（提前 30 分钟那一刻允许），右端 `<`（没收时刻起就不能再手动标到店，只能走 NS-004 的管理员撤销流程）。

### 3. 撤销没收（NS-004）

把现有的手动 **No-show** 按钮**去掉**（原因见下方"需要你确认"），改成管理员专属的 **Revert to Arrived** 按钮，仅在 `state == 'no_show'` 时可见，权限对齐 RF-005 的做法（`group_billiard_manager`，员工没有）。复用一个小向导（参考 4.3 的 `qclub.deposit.refund` 加 `mode` 字段的做法，这次给它再加一个 `mode = 'no_show_revert'`，弹窗要求填写原因），确认后：

- `state`: `no_show` → `arrived`
- 若 `deposit_state == 'forfeited'`：改回 `'paid'`（押金重新可用于结算，ST-006 要用）
- 新增 `no_show_revert_reason`（Char）、`no_show_revert_operator_id`（Many2one res.users）、`no_show_revert_at`（Datetime），记录原因、操作员、时间——和 4.3 `refund_reason`/`refund_operator_id` 同样的审计字段风格

### 4. 邮件

新增一个 QWeb 邮件模板 `qclub_billiard.no_show_email`，参照 `deposit_email` 的样式。文案两种：
- 有没收押金：「Your booking was marked as no-show; your $X deposit has been forfeited.」
- 没有押金可没收（电话预约）：「Your booking was marked as no-show.」

不像押金邮件那样限定 `booking_channel == 'online'`——电话预约的顾客同样应该知道自己被标记未到场，只是文案不提押金。只要 `partner_id.email` 有值就发。

### 5. 对账口径（为 4.6 铺垫，4.4 本身不做报表）

`no_show_at` 这个新字段将是 ST-009"没收计入置为未到场…当天"的依据，4.4 先把这个时间戳记录准，4.6 直接读它。

## 测试要点（边界 + 反向，按标准覆盖）

- 边界：`start + wait_minutes` 恰好等于 now（没收）vs 早 1 分钟（不没收）
- 边界：到店窗口左端恰好 `start - 30min`（允许）vs 早 1 分钟（拒绝）；右端恰好没收时刻（拒绝，已经 no_show 了）
- 反向：非 confirmed 状态点 "Mark Arrived" 被拒绝
- 反向：员工（非管理员）点不到 "Revert to Arrived"
- 反向：no_deposit（电话预约）没收后 deposit_state 不变，没有押金字段被动
- 撤销后押金变回 'paid'，可用于后续结算（为 4.5 铺垫，建一个占位断言）
- cron 跑两次不重复没收、不重复发邮件（状态已变为 no_show，第二次 search 不会再选中）
- 多公司隔离：cron 只处理 qclub.booking 记录，不影响 AUSHARE
- 邮件：有押金 vs 无押金两种文案都测到

### 设计

新增 `_queue_arrival_email()`（`booking_no_show.py`），和现有 `_queue_no_show_email()` 完全同样的写法：不限制 `booking_channel`（不像 `cancellation_email` 那样只对 `online` 发——那是 task-4.4-v1-01 记录的既有问题，这里不复用那个限制），只要 `partner_id.email` 和 `config.booking_email_from` 都有值就发，失败吞异常只记日志（`_logger.exception`），不影响状态流转。

新增 QWeb 模板 `qclub_billiard.arrival_email`（样式照抄 `no_show_email`），文案：「Your booking is confirmed as arrived. See you at the table!」，带预约编号、台桌、时段；不显示金额或结算信息（结算是 4.5 的事）。

两个调用点：
- `action_arrive()`：`super().action_arrive()` 成功后调用（员工在等到窗口内手动标到店）
- `_revert_no_show()`：写完 `state: 'arrived'` 之后调用（管理员撤销未到场，同样算"变为已到店"）

两处都不去重做特殊处理——各自只有一条状态转换路径能走到调用点（`action_arrive` 要求当前是 `confirmed`；`_revert_no_show` 要求当前是 `no_show`），正常使用不会对同一个"到店事件"发两封邮件。

### 测试要点（追加到 `test_no_show.py`，按边界/反向标准）

- `action_arrive()` 成功后发出到店邮件，文案不含金额
- `_revert_no_show()` 成功后也发出到店邮件
- `partner_id.email` 为空（如没留邮箱的电话预约）时静默跳过，不报错
- 两条路径各自只发一封，不重复（用 `mail.mail` 计数断言）
- 多公司隔离：邮件内容里的公司名取自 `booking.website_id.company_id`，不泄露到 AUSHARE

# 任务 1.5 设计说明：访问权限与 AUSHARE 隔离

分支：`feat/p1-5-access-isolation`　状态：**已评审**（2026-11-05：问题 1、3、4 按建议方案确认；问题 2 修改为"门户用户可读桌台和营业时间，不可读配置，均不可修改"）
对应规格（4 条）：SEC-002、SEC-003、ISO-001、ISO-002
实现方式：评审通过后由 Codex 编码，Claude Code 运行测试并独立审查
修改范围：`addons/qclub_billiard`、`tools/`、`docs/`；如第八节问题 3 获批，另含 `Makefile` 与 `.github/workflows/ci.yml`

## 一、背景

生产库里 Q Club 与 AUSHARE **共用一个数据库和一个公司**，隔离只能靠 `website_id` 和权限。到任务 1.4 为止，预约只对后台的球厅员工 / 管理员开放；门户用户（网站注册顾客）和匿名访客完全没有权限。阶段 2 网站预约上线前，需要先把门户用户能看到什么、在哪个网站能看到定下来。

## 二、门户用户只能看自己的预约（SEC-002）

- 访问权限：门户组（`base.group_portal`）对 `qclub.booking` **只读**（不能建、改、删；网站下单在阶段 2 由服务端代为创建）
- 记录规则（只作用于门户组）：

  ```
  [('partner_id', '=', user.partner_id.id), ('website_id', '=', website.id)]
  ```

  - 第一个条件：只能看到自己名下的预约，看不到他人的
  - 第二个条件：只在预约所属网站上可见（见第三节）
- 门户组对 `qclub.table`、`qclub.table.type` 只读（桌台名称、类型、单价本来就会在网站上公开展示），记录规则限定 `website_id = 当前网站` 且只看启用的
- 门户组对 `qclub.opening.hours` **只读**（营业时间对顾客公开，2026-11-05 评审确认），记录规则限定 `website_id = 当前网站`；不能新建、修改、删除
- 门户组对 `qclub.config` **不开放**：阶段 2 的页面需要配置值（如押金比例）时，由服务端读取并只返回必要字段
- 匿名访客（`base.group_public`）：不开放任何模型权限；阶段 2 的占用网格由服务端接口提供，且不返回个人信息（WEB-002）

## 三、按网站隔离（SEC-003）

- 记录规则里的 `website` 由 Odoo 的 website 模块提供：网页请求时是当前访问的网站；**后台或直接调用接口时为空，此时门户用户什么都看不到**（默认安全）
- 效果：同一个门户账号（生产库两个网站共用账号体系），在 `qclub.localhost`（Q Club）能看到自己的预约，在 `aushare.localhost`（AUSHARE）看不到任何预约数据，也看不到桌台
- 后台：不属于球厅员工组的内部用户（如 AUSHARE 员工）对预约、桌台、配置、营业时间都没有访问权限（1.1 / 1.3 已如此，本任务补测试确认）
- 球厅员工 / 管理员：不加网站过滤，能看到所有网站的预约（目前只有 Q Club 有预约）

## 四、AUSHARE 不受影响（ISO-001）

规格要求"安装前后对比"。分两层：

1. **模块内测试**（每次 `make test` 运行）：
   - 本模块安装的所有数据记录（`ir.model.data` 中 module = `qclub_billiard`）只属于白名单类型：本模块自己的模型、视图、动作、菜单、用户组、权限、记录规则、序列、定时任务；**不得**包含网站页面、网站菜单、产品、邮件模板、支付方式、继承网站 / 门户 / 商城模板的视图
   - AUSHARE 网站首页和 `/shop` 能正常打开（HTTP 200），页面里不出现 "Billiard"、"Booking" 等本模块的文字
2. **安装前后指纹对比**：新增 `tools/iso_fingerprint.py`，对一个数据库生成 AUSHARE 网站的"指纹"（AUSHARE 的页面、网站菜单、视图、产品、邮件模板的数量和内容摘要）。新增 `make iso-check`：分别对基础模板库 `qclub_base`（未装本模块）和测试库 `qclub_test`（已装本模块）生成指纹并比较，有差异则失败并列出差异项。CI 在 `make test` 后运行它
   - 阶段 6 上线彩排时，再在生产库副本上用同一工具对比（`progress.md` 风险表已列）

## 五、不改核心逻辑（ISO-002）

- 现状：本模块没有继承任何 Odoo 核心模型，只新增了自己的模型
- 新增一个测试：遍历注册表，列出本模块对非本模块模型的所有扩展；目前应为空。以后如确需扩展核心模型（例如阶段 4 给支付记录加字段），必须把它加进测试里的白名单并说明理由，审查时一眼可见
- 同一测试检查本模块没有覆盖核心模型的方法（`create` / `write` / `_compute_*` 等）

## 六、测试（新增 `tests/test_access_isolation.py`，HTTP 测试另放 `tests/test_isolation_http.py`）

| 规格 | 要点 |
|---|---|
| SEC-002 | 门户顾客 A 能读自己的预约；读不到顾客 B 的预约（搜索结果不含、直接读取报 AccessError）；不能新建、修改、删除任何预约；能读营业时间但不能新建、修改、删除；不能读配置 |
| SEC-003 | 在 Q Club 网站上下文中，顾客 A 能看到自己的预约、启用的桌台和 Q Club 的营业时间；在 AUSHARE 网站上下文中看不到任何预约、桌台和营业时间；没有网站上下文（后台 / 直接接口）时看不到；匿名访客没有任何权限；非球厅的内部用户读不到预约、桌台、配置、营业时间 |
| ISO-001 | 第四节第 1 层的数据白名单检查；`HttpCase`：AUSHARE 首页、`/shop` 返回 200 且不含本模块文字（`@tagged("post_install", "-at_install")`） |
| ISO-002 | 第五节的注册表检查 |

测试中按名称查找网站，不硬编码 id；网站上下文用 Odoo 测试中模拟当前网站的标准方法设置。

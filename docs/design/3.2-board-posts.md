## 一、用户看到什么

全部在 `/billiard/booking` 内，不跳转页面：

```
日期选择
网格：普通占用格灰色不可点；有帖子的格子显示 "Join · 2"；自己的预约显示 "Yours"
面板（网格下方，同一位置，同时只显示一个）：Selected booking（选空闲格）或 帖子面板（点标记）
当日列表：Players wanted on Fri 13 Nov
```

| 操作 | 结果 |
|---|---|
| 点带标记的格子，或当日列表的一条 | 打开帖子面板并滚动到可见位置；显示名按 BRD-001 |
| 点自己已确认、未发帖的预约 | 面板显示 **Find players** 表单；首次需勾选社区须知 |
| 点自己待付押金的预约 | 面板提示 "Your booking must be confirmed before you can find players." |
| 点自己已发帖的预约 | 打开自己的帖子 |
| 点空闲格 | 帖子面板关闭，恢复原有的选时段流程（2.2 不变） |
| 未登录点 Find players / 登录相关操作 | 跳转登录，返回预约页并打开同一面板 |

一条预约跨几小时，占用的每一格都显示标记，点哪一格都是同一个帖子。标记文字：有名额 "Join · 2"，名额满 "Full"（仍可点开查看）。本任务还没有申请功能，名额暂时等于需要的人数；申请按钮在 3.3 加入。

确认页：预约已确认、未开始、未发帖且网站开启留言板时，显示 **Find players**，链接 `/billiard/booking?date=…&booking=<编号>`，自动打开表单。

## 二、数据模型

**`qclub.board.post`（新）**

| 字段 | 说明 |
|---|---|
| `booking_id` | 必填，`ondelete="restrict"`，**数据库唯一约束**（每条预约最多一个帖子，BRD-004） |
| `website_id`、`partner_id` | 取自预约，存储，用于记录规则和查询 |
| `message` | 必填，纯文本 1–500 字符（去首尾空格后） |
| `level` | 选择：`any` / `beginner` / `intermediate` / `advanced` |
| `players_needed` | 整数，1 到配置的 "Max Players per Post" |
| `state` | 选择：`open` / `closed`，默认 `open` |

时段、桌台、价格都不存，一律取自预约，员工改期后帖子自动跟着变。

**"是否开放"按读取时计算**（BRD-016，不依赖定时任务）：`state == open`、预约为已确认、开始时间在未来。预约被取消时，即使 3.3 的联动尚未做，帖子也不会显示。

**`qclub.board.terms`（新）**：`website_id`、`partner_id`、`accepted_at`；`UNIQUE(website_id, partner_id)`（BRD-029）。

## 三、接口

**不修改占用接口**：已合并的隐私测试 `test_web_002_public_whitelist_privacy_and_website` 固定了它的字段集合，帖子数据放在独立接口里，也更容易审查隐私。因此把 BRD-003 中"占用接口新增的帖子摘要"改为"帖子摘要接口"。

| 路由 | 类型 | 权限 | 作用 |
|---|---|---|---|
| `/billiard/booking/board` | jsonrpc | 公开（受 BRD-009 开关约束） | 输入日期；返回当日开放帖子的摘要；登录时另返回**本人**当日的预约 |
| `/billiard/booking/post` | jsonrpc | 公开（同上） | 输入帖子编号；返回面板内容；已关闭返回 `closed` 只读内容 |
| `/billiard/booking/post/create` | jsonrpc | 登录用户 + CSRF | 输入本人预约编号、消息、水平、人数、是否同意须知；创建帖子 |

- 未开启 Online Board 的网站（含 AUSHARE）全部 404（BRD-027）
- 摘要字段白名单：帖子 id、桌台 id、开始时间（UTC）、小时数、时间文字、桌台名、显示名、水平、剩余名额。**不含预约编号和任何顾客字段**；本人预约的编号只返回给本人
- 写操作：只接受白名单参数；预约按"编号 + 当前顾客 + 当前网站"查找，查不到一律同样的错误；发帖条件（BRD-004）在服务端校验
- 门户 / 公开用户对新模型**没有模型权限**，只经路由，路由校验后用 `sudo()`（BRD-026）；员工只读，管理员读写，均不可删除
- 记录规则按 `website_id`（BRD-027）
- 地址参数 `post`、`booking` 只用于打开界面，内容由接口重新校验

## 四、前端

- 在 `booking_grid.js` 的占用网格加载后再请求帖子摘要，把标记加到格子上；请求失败不影响预约功能
- 帖子相关代码放新文件 `static/src/interactions/booking_board.js`，由网格调用，避免继续撑大现有文件
- 带标记的格子改为可点击（`role="button"`、键盘可操作、移除 `aria-disabled`）；**没有帖子的占用格保持不可点**（WEB-003）
- 所有用户内容用 `textContent`，不用 `innerHTML`；网址不转链接（BRD-025）
- 打开的帖子被关闭时，刷新网格并显示 "This post is closed."（沿用 2.2 的提示方式）
- 发帖成功后刷新网格和面板，不跳转

要点：
1. 新 cron `_cron_mark_no_show`（每分钟，仿照 `qclub_booking.py` 里已有的 `_cron_expire_pending` 的写法和 `data/qclub_booking_cron.xml` 的注册方式），把超过等待时长仍是 `confirmed` 的预约标记为 `no_show`；已付押金的没收（`deposit_state` → `forfeited`），电话预约（`no_deposit`）只改状态。新增字段 `no_show_at`（Datetime）记录发生时间。
2. `action_arrive` 加时间窗校验（`start - 30min <= now < start + no_show_wait_minutes`，用快照字段，不用配置当前值），窗口外 `UserError`。
3. 去掉表单上现有的手动 "No-show" 按钮和 `action_no_show` 的直接暴露；改成只有 `qclub_billiard.group_billiard_manager` 能看到的 "Revert to Arrived" 按钮（`state == 'no_show'` 时可见），复用 `qclub.deposit.refund` 向导，给它加 `mode = 'no_show_revert'`，确认时必填原因。撤销后：`state` → `arrived`，若 `deposit_state == 'forfeited'` 改回 `'paid'`；新增字段 `no_show_revert_reason`（Char）、`no_show_revert_operator_id`（Many2one res.users）、`no_show_revert_at`（Datetime）。
4. 新邮件模板 `qclub_billiard.no_show_email`（参照已有的 `deposit_email` 风格），不限 `booking_channel`，只要 `partner_id.email` 有值就发；按有没有押金给两种文案（设计说明第 4 节已给出英文文案）。
5. 新字段都加入 `tools/make_report.py` 用到的需求覆盖检查（如果该脚本按字段名或方法名匹配，确认 NS-001 到 NS-005 都能被扫描到；否则在测试 docstring/名字里带上编号即可，和已有任务一致）。

# 任务 4.5 设计：现场结算（ST-001、ST-005–007）

状态：**待批准**

## 规格回顾

- ST-001（phase1-2.md F）：现场结算：员工录入实际台费 → 扣除已付押金 → 余额以 EFTPOS 或现金收取 → 预约变"已完成"
- ST-005：已到店的预约在后台点 **Settle**：实际台费默认等于预约台费，可修改（加时、优惠等），修改时必须填写原因
- ST-006：余额 = 实际台费 − 已付押金。余额大于 0 时选择 EFTPOS 或现金（只记录方式和金额，不连接刷卡机）；余额等于 0 直接完成；实际台费少于押金时按第 H 节第 4 条处理
- ST-007：结算后预约变为已完成，结算记录不可修改；如需更正，由管理员操作并记录原因
- phase4.md 第 H 节第 4 条（已批准）：实际台费少于押金，押金不退，可抵扣实际台费，差额不退；确需退还走 RF-005 例外退款
- PAY-010：backoffice/电话预约没有在线押金（`deposit_state = 'no_deposit'`），结算时全额收取

## 现状（占位代码）

`qclub_booking.py` 目前：

```python
def action_complete(self):
    return self.write({"state": "done"})
```

`ALLOWED_TRANSITIONS` 已经只允许 `arrived -> done`（BK-010），这条不用改。表单上现有一个任何员工可点的占位 **Complete** 按钮，要按规格重做成 **Settle**（弹窗）。

## 设计

### 1. 新增字段（`qclub_booking.py` 或新文件 `booking_settlement.py`，仿 4.3/4.4 的审计字段写法）

```python
actual_table_fee = fields.Monetary(readonly=True, copy=False)
settle_reason = fields.Char(readonly=True, copy=False)
settle_operator_id = fields.Many2one('res.users', readonly=True, copy=False)
settle_at = fields.Datetime(readonly=True, copy=False)
balance_amount = fields.Monetary(readonly=True, copy=False)
balance_method = fields.Selection([('eftpos', 'EFTPOS'), ('cash', 'Cash')], readonly=True, copy=False)
settle_correction_reason = fields.Char(readonly=True, copy=False)
settle_correction_operator_id = fields.Many2one('res.users', readonly=True, copy=False)
settle_correction_at = fields.Datetime(readonly=True, copy=False)
```

`write()` 保护这些字段不被直接改（同 `booking_no_show.py` 的 `AUDIT_FIELDS` 写法），只能通过下面的结算方法写入。

### 2. `deposit_state` 新增一个值：`applied`（押金抵扣）

现有 `deposit_state` 枚举没有"押金被抵扣进台费"这个状态（`paid`/`refunded`/`forfeited`/`no_deposit`/`refund_failed`/`awaiting` 都不对）。ST-008（4.6 日对账，这次不做但要为它铺垫）把"押金抵扣"列为独立的一类资金事件，和"没收"分开统计，所以结算消费掉押金时，`deposit_state` 要改成新的 `applied`，不能复用 `forfeited`（那个专属未到场/取消没收）。这是新增一个 Selection 选项，不改变现有值的含义，不影响已有测试。

backoffice/电话预约（`deposit_state == 'no_deposit'`）结算时没有押金可抵扣，这个字段保持 `no_deposit` 不变，直接全额收余额。

### 3. 结算向导 `qclub.booking.settle`（新 TransientModel，仿 `qclub.deposit.refund` 的 `mode` 写法）

```python
mode = fields.Selection([('settle', 'Settle'), ('correct', 'Correct Settlement')], required=True, default='settle')
booking_id = fields.Many2one('qclub.booking', required=True, readonly=True)
actual_table_fee = fields.Monetary()  # default = booking.table_fee
reason = fields.Char()
balance_due = fields.Monetary(compute='_compute_balance', readonly=True)  # max(0, actual - paid_amount)
method = fields.Selection([('eftpos', 'EFTPOS'), ('cash', 'Cash')])
```

- `balance_due` 实时算给员工看："台费 $60，已付押金 $20，还需收 $40"；实际台费低于已付押金时显示 "$0（押金 $X 不予退还）"，文案直接提醒不退。
- 金额改了（`actual_table_fee != booking.table_fee`）必须填 `reason`（ST-005）；没改可以不填。
- `balance_due > 0` 必须选 `method`；`balance_due == 0`（含实际台费 ≤ 已付押金的情况）不需要选方式，直接完成。
- `mode == 'correct'` 时：仅管理员能用（`group_billiard_manager`，权限检查写法照抄 `deposit_refund.py` 的 `create()`/`write()` 模式），`reason` 必填（不管金额有没有变，ST-007 要求更正必须留原因），可以重新填 `actual_table_fee` 和 `method`（更正等于按新数字重跑一次结算计算，只是多了强制原因 + manager 权限这两条，不单独做一套"只能改金额不能改方式"的限制，保持简单一致）。

### 4. `qclub_booking.py` / 新文件里的结算方法

```python
def action_settle(self):
    self.ensure_one()
    if self.state != 'arrived':
        raise UserError(_('Only arrived bookings can be settled.'))
    return {
        'type': 'ir.actions.act_window', 'res_model': 'qclub.booking.settle',
        'view_mode': 'form', 'view_id': self.env.ref('qclub_billiard.booking_settle_form').id,
        'target': 'new', 'context': {'default_booking_id': self.id, 'default_mode': 'settle'},
    }

def action_correct_settlement(self):
    self.ensure_one()
    if not self.env.user.has_group('qclub_billiard.group_billiard_manager'):
        raise AccessError(_('Only billiard managers can correct a settlement.'))
    if self.state != 'done':
        raise UserError(_('Only completed bookings can be corrected.'))
    return {
        'type': 'ir.actions.act_window', 'res_model': 'qclub.booking.settle',
        'view_mode': 'form', 'view_id': self.env.ref('qclub_billiard.booking_settle_correct_form').id,
        'target': 'new', 'context': {'default_booking_id': self.id, 'default_mode': 'correct',
                                      'default_actual_table_fee': self.actual_table_fee,
                                      'default_method': self.balance_method},
    }

def _settle(self, actual_table_fee, reason, method, correction=False):
    self.ensure_one()
    self._lock_tables(self.table_id.ids)
    self.env.cr.execute(SQL('SELECT id FROM qclub_booking WHERE id = %s FOR UPDATE', self.id))
    balance_due = max(self.currency_id.round(actual_table_fee - self.paid_amount), 0.0)
    if balance_due and not method:
        raise ValidationError(_('Select how the balance was paid.'))
    if actual_table_fee != self.table_fee and not (reason and reason.strip()):
        raise ValidationError(_('A reason is required when the actual table fee differs from the booking.'))
    if correction and not (reason and reason.strip()):
        raise ValidationError(_('A reason is required to correct a settlement.'))
    values = {
        'actual_table_fee': actual_table_fee, 'balance_amount': balance_due,
        'balance_method': method if balance_due else False,
    }
    if correction:
        values.update({
            'settle_correction_reason': reason.strip(), 'settle_correction_operator_id': self.env.uid,
            'settle_correction_at': fields.Datetime.now(),
        })
    else:
        values.update({
            'settle_reason': (reason or '').strip() or False, 'settle_operator_id': self.env.uid,
            'settle_at': fields.Datetime.now(),
        })
        if self.deposit_state == 'paid':
            values['deposit_state'] = 'applied'
        super(QclubBooking, self).write({'state': 'done'})  # the one allowed arrived->done transition
    self._write_deposit(values)  # or equivalent helper that bypasses the AUDIT_FIELDS guard
    self.sudo().message_post(body=_(
        'Booking settled. Actual table fee: %(fee)s. Balance: %(balance)s%(method)s. Operator: %(operator)s.',
        fee=format_amount(self.env, actual_table_fee, self.currency_id),
        balance=format_amount(self.env, balance_due, self.currency_id),
        method=f' via {method}' if method else '', operator=self.env.user.display_name,
    ))
```

（具体怎么绕开 `AUDIT_FIELDS` 的 `write()` 保护，跟 4.3/4.4 一样用 `super().write()` 或者单独的内部写入路径，Codex 写的时候参照 `booking_no_show.py`/`booking_deposit.py` 已有的模式。）

### 5. 向导的两个方法

```python
def action_confirm_settlement(self):
    self.ensure_one()
    if self.mode != 'settle':
        raise ValidationError(_('Use the settlement wizard to settle a booking.'))
    self.booking_id._settle(self.actual_table_fee, self.reason, self.method, correction=False)
    return {'type': 'ir.actions.act_window_close'}

def action_confirm_correction(self):
    self.ensure_one()
    if self.mode != 'correct':
        raise ValidationError(_('Use the correction wizard to correct a settlement.'))
    self.booking_id._settle(self.actual_table_fee, self.reason, self.method, correction=True)
    return {'type': 'ir.actions.act_window_close'}
```

## 测试要点（边界 + 反向，按标准覆盖）

- ST-005：金额不变不用填原因；金额变了不填原因被拒绝；填了原因能改
- ST-006 边界：余额恰好 0（实际台费等于已付押金）直接完成，不需要选支付方式；余额 > 0 必须选方式，没选被拒绝；实际台费 < 已付押金时余额为 0、不触发任何退款、押金多出的部分不退（断言 `refund_amount` 等退款字段没有被写入）
- no_deposit（backoffice/电话预约）结算：`paid_amount` 为 0，余额 = 全部实际台费，必须选支付方式；`deposit_state` 结算后仍是 `no_deposit`（没有押金可抵扣）
- 在线已付押金结算后 `deposit_state` 变成新增的 `applied`，不是 `forfeited`
- 反向：非 `arrived` 状态点不到 Settle（`confirmed`/`pending`/`done` 等）
- ST-007：结算完成后直接 `write()` 改 `actual_table_fee` 等字段被拒绝（审计字段保护）；员工点不到 Correct Settlement；管理员不填原因更正被拒绝；管理员填原因能更正，更正审计字段（`settle_correction_reason`/`operator_id`/`at`）正确记录，原 `settle_at`/`settle_operator_id` 保留不变（只加更正记录，不覆盖首次结算的痕迹）
- 多公司隔离：照搬现有模式测一遍

## 已确认的决定

1. `deposit_state` 新增 `applied`（押金抵扣）值，不复用 `forfeited`，为 4.6 日对账的"押金抵扣"统计口径铺垫
2. 更正结算（Correct Settlement）允许同时改实际台费和支付方式，原因必填且必须是管理员；不单独限制"只能改金额"或"只能改方式"
3. 实际台费少于已付押金时，余额记为 0，差额不退，也不走任何退款流程（RF-005 的例外退款是单独入口，不在这个向导里）

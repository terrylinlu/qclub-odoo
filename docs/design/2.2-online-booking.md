## 一、范围

| 规格 | 内容 |
|---|---|
| WEB-004 | 提交时服务端重新校验营业时间、整点、冲突、时长；不信任前端传来的价格、押金、状态 |
| WEB-005 | 冲突时提示 "This time slot has just been taken. Please choose another."，不创建任何记录 |
| WEB-006 | 提交需要登录；未登录先去登录，登录后回到原来的选择 |
| WEB-008 | 页面显示所选时段的台费和押金，与服务端计算一致 |
| WEB-009 | 距开始不足"免费取消时长"时显著提示 "This booking cannot be cancelled free of charge."；预约记录保存"创建时已在取消窗口内" |
| WEB-010 | 跨午夜的起止时间在页面、确认页、邮件中都正确 |

**不在本任务**：支付（阶段 4）；顾客查看 / 取消自己的预约（"My Bookings"，阶段 4）；顾客注册（沿用网站现有的登录 / 注册设置，本模块不改，因为它是两个网站共用的设置）。

## 二、页面流程

```
网格（2.1）→ 点同一桌台的连续空闲格 → 下方出现"选择摘要" → Book
   ├─ 未登录 → 登录页 → 回到预约页，自动恢复同一日期、桌台、时段（WEB-006）
   └─ 已登录 → 提交 → 成功：确认页 / 冲突：提示并刷新网格（WEB-005）
```

### 1. 在网格上选择

- 点一个空闲格 = 选中 1 小时；再点**同一桌台**相邻的空闲格，向前或向后延长；最多"最长连续小时数"（默认 4）
- 点另一张桌台的格子 = 重新开始选；再点已选的端点格 = 缩短；"Clear" 按钮清空
- 只能选空闲格；已占用、已过去的格子仍不可点（2.1 已有）
- 跨午夜可以连选（同一营业日内，例如周五 11:00 PM + 12:00 AM (next day)）
- 选中的格子高亮，并用 `aria-pressed` 标记；手机上点按同样可用

### 2. 选择摘要（WEB-008、WEB-009、WEB-010）

选中后，网格下方显示（数据来自服务端报价接口，不在浏览器里算钱）：

| 项目 | 示例 |
|---|---|
| 桌台 | [Demo] Table 1 · Chinese 8-Ball |
| 时间 | **Fri 6 Nov, 11:00 PM – Sat 7 Nov, 1:00 AM**（2 hours） |
| 台费 | $40.00 |
| 押金（现在应付） | **$20.00** (50%) |
| 取消提示（不足免费取消时长时） | 醒目的警告框："This booking cannot be cancelled free of charge." |
| 说明 | "Your table is held for 10 minutes while awaiting the deposit."（取自设置的锁定时长） |
| 按钮 | **Book**（未登录时显示 "Log in to book"） |

时间格式见第十节问题 1。

### 3. 登录后恢复选择（WEB-006）

- 未登录点 Book → 跳到 `/web/login?redirect=/billiard/booking?date=…&table=…&start=…&hours=…`
- 预约页读取这些参数：日期在可选范围内就打开该日期；格子仍然空闲就恢复选中并显示摘要；已被占用或已过去，则只打开日期并提示 "Your selected time is no longer available."
- 参数只是"恢复界面"用，提交时服务端照常全部重新校验

### 4. 提交与结果

- 已登录点 Book → 服务端创建预约 → 跳转到确认页
- 冲突（包括刚被别人抢先）→ 摘要处显示 WEB-005 的原文提示，并刷新网格；**不创建任何记录**
- 其他校验失败（已过去、超出营业时段、超过最长时长等）→ 显示对应的英文提示，不创建记录

### 5. 确认页 `/billiard/booking/confirmation/<预约编号>`

- 只有预约本人（同一顾客）能打开；其他人、未登录一律 404（不泄露预约是否存在）
- 显示：预约编号、桌台、时间（同摘要格式）、台费、押金、状态 "Awaiting deposit"
- **锁定剩余时间**：倒计时（例如 "Held for 9:41"）；到 0 后显示 "This hold has expired. Please make a new booking."（以服务端的 `lock_expire` 为准，倒计时只是显示）
- 创建时已在取消窗口内的，同样显示 WEB-009 警告
- 本阶段没有支付：页面写明 "Online deposit payment is coming soon. Our staff will contact you to confirm."（文字可改，见第十节问题 3）

## 三、服务端接口

| 路由 | 类型 | 权限 | 作用 |
|---|---|---|---|
| `/billiard/booking`（2.1 已有） | http GET | 公开 | 增加读取 `date / table / start / hours` 参数（只用于恢复界面） |
| `/billiard/booking/quote` | jsonrpc | 公开（受 CFG-005 "登录才能看占用"约束） | 输入桌台、开始时间、小时数；返回时间文字、台费、押金、是否在取消窗口内、锁定分钟数；不创建记录 |
| `/billiard/booking/submit` | jsonrpc | **登录用户** | 输入同上；创建预约；返回确认页地址，或错误代码和提示 |
| `/billiard/booking/confirmation/<name>` | http GET | 登录用户，仅本人 | 确认页 |

- 所有接口只在开启 Online Booking 的网站可用（与 2.1 相同，AUSHARE 返回 404）
- 桌台必须属于当前网站且启用；开始时间必须是网格上的整点；小时数为整数
- **价格、押金、状态一律由服务端计算**（WEB-004）；客户端即使传了这些字段也直接丢弃
- 报价和创建共用同一个模型方法计算金额，保证页面与记录一致（WEB-008）
- 创建：以当前登录顾客为 `partner_id`；门户用户本身没有创建预约的权限（阶段 1 的权限设计），所以接口在完成上面的检查后用 `sudo()` 创建，仍走模型里全部的校验、表锁和排他约束（BK-004/005）
- 冲突识别：模型的两处冲突提示（Python 检查与数据库排他约束）改为抛出一个专用的冲突异常（仍是 `ValidationError` 的子类，后台显示的文字不变），接口据此返回 WEB-005 的原文提示

## 四、预约记录的新字段（WEB-009）

| 字段 | 说明 |
|---|---|
| `created_in_cancel_window` | 布尔，创建时计算：`start − 创建时间 < free_cancel_hours`，之后不再改变（改期不重算，记录的是"下单时的事实"）；所有新预约都计算，包括后台创建的。后台表单和列表可见（标签 "Booked Within Cancellation Window"） |
| `booking_channel` | 选择：`online` / `backoffice`，记录来源；网上提交的为 `online`。用于决定是否发邮件，也方便以后统计 |

已有预约升级后：`created_in_cancel_window` 为空（未知），`booking_channel` 为 `backoffice`。

## 五、防止占位滥用

阶段 2 没有付款，一个账号可能连续提交、把所有桌台都锁 10 分钟。建议：**同一顾客同时最多 2 个待付押金的网上预约**，超过时提示 "You already have unpaid bookings. Please wait for them to be confirmed or expire."（数量做成设置项，见第十节问题 2）。后台员工建的预约不受限。

## 六、邮件 "Booking received – awaiting deposit"（按穿刺 2 结论）

- 只在**网上提交成功后**发给顾客；后台建的预约本阶段不发
- **不用 Odoo 默认版式**：本模块自带 Q Club 版式，标题、logo、链接都取自 Q Club **网站**；页脚是 Q Club 的联系方式（新设置项）；不出现公司名、AUSHARE 的联系方式、"Powered by Odoo"
- 发件人：新设置项 **Booking Email From**（例如 `Q Club <bookings@cueclub.com.au>`）；为空时不发邮件，并在后台设置页提示需要填写（不回落到公司邮箱，避免以 AUSHARE 的名义发出）
- 链接一律用 Q Club 网站的域名（不用系统基础网址 `shop.aushare.com.au`）
- 内容：预约编号、桌台、时间（同摘要格式，覆盖跨午夜，WEB-010）、台费、押金、锁定到期时间、取消窗口警告（如适用）、确认页链接
- 发送走 Odoo 的邮件队列，不阻塞提交；发送失败不影响预约本身
- 新设置项（Q Club 的 Settings 页）：**Booking Email From**、**Contact Phone**、**Contact Email**（用于页脚）
- 生产要真正发出，需要 Q Club 自己的发件邮箱和发件服务器（穿刺 2 第四节），记入 `progress.md` 第八节；本阶段不对外上线，不受影响

## 七、隔离与安全

- AUSHARE 上所有新路由 404；网格、报价、提交都只认当前网站的桌台（ISO 测试扩充）
- 确认页按"本人"判断，别人的编号一律 404；报价接口不返回任何其他顾客信息（沿用 WEB-002）
- 提交接口要求登录和 CSRF 防护（Odoo jsonrpc 自带）；只接受白名单参数
- 邮件模板只渲染本预约的数据；所有页面文字用 `textContent` / QWeb 转义，不拼接 HTML

## 十一、验收后修改（2026-11-07，已确认）

验收时两个窗口反复测试，出现"格子显示空闲、却谁都订不了"的情况。实际是时段已被其中一人提交保留（待付押金，10 分钟），但页面一直显示旧状态。修改：

1. **报价发现冲突时刷新网格**：选中格子后，报价接口若返回冲突，与提交冲突相同处理——刷新网格、清除选择和"Loading quote…"、显示红色提示框并滚动到可见位置
2. **从浏览器"后退"返回预约页时重新加载**：页面从浏览器缓存还原（`pageshow` 且 `persisted`）时，重新加载占用网格，不显示过期的选择或提示
3. **自己保留中的时段**：冲突的预约属于当前登录顾客且为待付押金时，报价和提交都返回 `own_hold`，提示 "You already hold this time slot (QB2026-00027, awaiting deposit)." 并附确认页链接；不显示 "taken"
4. **说明保留会自动释放**（修改 WEB-005 规格文字）：冲突提示后另起一行 "Slots awaiting a deposit are released automatically if not paid within N minutes."（N 取自 Unpaid Hold 设置）

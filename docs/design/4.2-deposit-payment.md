# 任务 4.2 设计说明：网上付押金

状态：**已批准**（2026-11-12，第六节各项均同意；重复付款按 PAY-014 改为人工处理）
对应规格：`docs/spec/phase4.md` PAY-001 至 PAY-011、PAY-013、PAY-014；穿刺 3 报告第四节（`docs/spikes/03-stripe-deposit.md`）

## 一、做完后顾客看到什么

1. 提交预约后来到确认页，状态为 Awaiting Deposit。页面上显示押金金额、保留截止时间，**下方直接是付款表单**（Odoo 自带，Stripe 的银行卡输入框），以及 **Pay deposit** 按钮。距开始不足 24 小时的预约，按钮旁显示 "This booking cannot be cancelled free of charge."（WEB-009）。
2. 付款成功后回到确认页，状态变为 **Confirmed**，收到 "Deposit received – booking confirmed" 邮件。
3. 卡被拒绝时，页面提示原因，预约仍为 Awaiting Deposit，可以换卡重试。
4. 后台预约表单新增 **Deposit** 区域，只读显示：押金状态、实付金额、付款时间、Stripe 交易号。

## 二、怎么做

照 Odoo 销售订单在线付款的现成模式，不另造支付流程（穿刺 3 已验证）。

| 部分 | 做法 |
|---|---|
| 交易关联预约 | 在 Odoo 的付款交易上加一个"所属预约"字段；交易编号以预约编号开头（如 `QB2026-00172`），在 Stripe 控制台里一眼能对上 |
| 付款页 | 确认页里渲染 Odoo 自带的付款表单。表单只列出对当前网站、当前公司可用的支付方式，所以 AUSHARE 永远看不到 Q Club 的 Stripe |
| 创建交易 | 本模块自己的路由，**由服务端**按预约的押金、币种、公司生成交易；只允许预约本人、在本网站、预约仍为 Awaiting Deposit 且未过保留期时付款（PAY-011）。不使用 Odoo 的通用付款链接（穿刺 3 发现其校验码不绑定预约） |
| 付款成功 | 在交易的后处理里处理：核对实收金额和币种等于押金（不一致则不确认，后台标出，PAY-005），把预约改为 Confirmed，记录金额、时间、Stripe 交易号，发邮件。同一笔交易重复通知只处理一次（PAY-004） |
| 保留期已过才到账 | 时段仍空闲就恢复并确认；已被别人订走就自动全额退款并发邮件说明（PAY-006）。这需要给状态流转加一条只在付款成功时才允许的"Expired → Confirmed" |
| 不生成会计凭证 | 关联预约的交易，以及它们的退款交易，跳过 Odoo 自动生成付款凭证（做法 A）。其他交易不受影响 |
| 押金状态 | 预约新增押金状态：Awaiting payment、Paid、No online deposit。之后的退款、没收、抵扣在 4.3–4.5 再加 |
| 电话预约 | 员工在后台直接 Confirm 的预约，押金状态为 No online deposit（PAY-010） |
| 后台显示 | 押金区域只读；任何人都不能改金额（PAY-009） |

## 三、需要你决定

1. **付款表单放在哪里**：建议**直接放在确认页**（提交后少点一次）；另一种是确认页只放一个按钮，点了再打开付款页。
2. **付款时保留期快到了**：保留期 10 分钟，顾客做 3D Secure 验证可能要一两分钟。建议：顾客点 Pay deposit 时，如果保留期剩不到 5 分钟，**延长到从现在起 5 分钟，只延长一次**，避免付到一半预约过期。即使仍然过期，也有 PAY-006 兜底。
3. **重复付款**（2026-11-12 你的决定，PAY-014）：按预约判断，同一预约已有一笔成功付款后又到账一笔，就是重复付款。**不自动退款**：预约标记 **Payment needs attention**，后台可筛选、表单顶部醒目提示，并发提醒邮件到 Q Club 的联系邮箱；由**管理员**点 **Refund extra payment** 原路退回，必须填写原因。预约已付过押金后，服务端拒绝再为它创建付款，确认页也不再显示付款表单，所以只有两个窗口几乎同时付款才会出现。付款到账时预约已过期且时段被别人订走的情况不变，仍按 PAY-006 自动退款。

## 四、测试与演示环境（需要你批准）

穿刺报告里我说过要改 `Makefile`，让测试基础库预先装好 Stripe 模块。现在有更好的办法，**不需要改 `Makefile`**：

- **自动测试**：用 Odoo 支付模块自带的测试工具，模拟付款成功、失败、重复通知、过期到账，不连接 Stripe。CI 也一样。
- **e2e（本机和 CI）**：在演示库里安装 Odoo 自带的模拟支付模块 `payment_demo`，给 Q Club 启用一个 "Demo" 支付方式，页面上能选"付款成功 / 失败"，不需要密钥和网络。**需要你批准修改 `docker/demo_data.py`**。生产不会安装这个模块。
- **本机演示真实 Stripe**：新增脚本 `tools/stripe_demo.sh`（脚本里不含任何密钥），做三件事：在演示库安装 `payment_stripe`，从你的密钥文件配置 Q Club 的 Stripe（测试模式），启动付款通知转发。启用 Stripe 时停用 Demo 支付方式，演示结束后可以恢复。
- 测试密钥的检查写成模块里的一个小方法（只接受 `pk_test_` / `sk_test_`，遇到 `_live_` 拒绝），脚本调用它，也方便写测试（PAY-002）。

模块只新增依赖 `account_payment`（随 `website_sale` 已安装），不依赖 `payment_stripe` 或 `payment_demo`，所以 AUSHARE 的隔离检查不受影响。

## 三、哪个网站显示预约页（WEB-001）

不写死网站 id 或名称。在 `qclub.config`（每个网站一条）上加开关：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `online_booking` | Boolean | False | 该网站是否开放在线预约页 |
| `occupancy_requires_login` | Boolean | False | CFG-005：登录后才能查看占用 |

- `/billiard/booking` 和占用接口：当前网站没有配置、或 `online_booking` 关闭 → **404**（不是 403，避免暴露页面存在）
- 演示数据和测试为 Q Club 打开 `online_booking`；生产上线时由管理员在 Q Club 的 Settings 里打开
- 两个开关只有球厅管理员可改（沿用 CFG-004 的权限）
- 只在本模块自己的模型上加字段，不扩展任何核心模型（ISO-002 不受影响）

## 四、占用接口（WEB-002、WEB-003、WEB-007、TBL-006）

`POST /billiard/booking/occupancy`，`type='jsonrpc'`，`auth='public'`，`website=True`。参数：`date`（`YYYY-MM-DD`，营业日）。

**返回**（只含下列字段，测试用白名单断言）：

```json
{
  "business_date": "2026-11-06",
  "available_dates": {"min": "2026-11-06", "max": "2026-11-20"},
  "currency": "AUD",
  "slots": [
    {"start": "2026-11-06T03:30:00Z", "label": "2:00 PM", "next_day": false},
    {"start": "2026-11-06T13:30:00Z", "label": "12:00 AM", "next_day": true}
  ],
  "tables": [
    {"id": 7, "name": "Table 1", "type": "Snooker", "hourly_price": 30.0,
     "slots": ["free", "occupied", "past", "free"]}
  ]
}
```

- **整点列**：取该营业日的营业时段（1.2 的 `_get_business_intervals`），按 UTC 每小时一格；`label` 为阿德莱德本地 12 小时制；本地日期晚于营业日时 `next_day = true`（TBL-006）。夏令时切换日自然正确，因为先在 UTC 上按小时切分，再换算本地标签
- **每格状态**：`free`、`occupied`（与有效占用预约重叠）、`past`（开始时间不晚于现在）。休息日返回空的 `slots`
- **Awaiting Deposit 锁定已过期但定时任务还没处理的预约**，按**空闲**显示（与 1.4 新建预约时的按需过期一致；接口只读，不在这里写数据库）
- **隐私**：只返回时间和状态，不返回预约编号、顾客、电话、邮箱；服务端用 sudo 读取，只挑选上面的字段
- **只显示**：当前网站、启用中的桌台（按排序）
- **日期范围**：今天（阿德莱德）到今天 + 最多提前天数；超出范围返回明确的错误
- **CFG-005**：开关打开且当前是匿名访客时，返回 `{"error": "login_required"}`，页面显示登录提示；登录后正常
- 同一请求里不做任何写操作

## 五、页面（WEB-001、WEB-003、TBL-006）

- 路由 `/billiard/booking`，网站布局（页头页脚沿用 Q Club 网站），英文界面
- 顶部：日期选择（只能选可预约范围内的日期），默认今天
- 网格：行 = 桌台（名称、类型、单价），列 = 整点；`occupied` / `past` 置灰并不可点击；跨午夜列标题显示 "12:00 AM (next day)"
- 手机：网格横向滚动，桌台名称列固定
- `Interaction`：读取日期 → 调占用接口 → 渲染网格；切换日期时重新加载
- 本任务网格只读；2.2 在此基础上加选择和提交

## 六、自动启用 `btree_gist`（穿刺 0 结论）

`qclub.booking.init()` 在创建排他约束之前执行 `CREATE EXTENSION IF NOT EXISTS btree_gist`。生产上 Odoo 的数据库账号是库所有者，必定成功；已启用时不做任何事。

| 规格 | 要点 |

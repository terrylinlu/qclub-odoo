# 修复：task-4.5-v1-01/02/03（客户侧结算展示 + My Bookings 对齐）

验收记录：`docs/acceptance/task-4.5.md` 第二节。三个问题一起修，出一个回归版本。

## 1. task-4.5-v1-01 / task-4.5-v1-02（同一根因，一起修）

**现状**：`addons/qclub_billiard/views/booking_templates.xml` 的 `booking_confirmation` 模板，
不管 `booking.state` 是什么，永远显示：
```xml
<p>Table fee: <span t-field="booking.table_fee"/></p>
<p>Deposit: <span t-field="booking.deposit_amount"/></p>
```
`booking.table_fee`/`deposit_amount` 是预约时的原价/应付押金，结算（`action_settle`/`action_correct_settlement`）
写的是 `actual_table_fee`/`balance_amount`/`balance_method`，模板完全没引用，所以客户确认页结算后仍显示原价，
也看不到实际付了多少钱。

**修复**：`state == 'done'` 时改成显示结算结果，其余状态保持原样不变：

```xml
<t t-if="booking.state == 'done'">
    <p>Table fee: <span t-field="booking.actual_table_fee"/></p>
    <p>Amount paid: <span t-esc="booking.paid_amount + booking.balance_amount"
                           t-options="{'widget': 'monetary', 'display_currency': booking.currency_id}"/></p>
    <p t-if="booking.balance_method">Balance paid via:
        <span t-out="dict(booking._fields['balance_method'].selection)[booking.balance_method]"/></p>
</t>
<t t-if="booking.state != 'done'">
    <p>Table fee: <span t-field="booking.table_fee"/></p>
    <p>Deposit: <span t-field="booking.deposit_amount"/></p>
</t>
```

- "Amount paid" = `paid_amount + balance_amount`：已付押金（结算时被标记为 `applied`，但金额字段
  `paid_amount` 不变）加上结算时收的尾款；没有尾款（`balance_amount = 0`）时就是押金/全款实收金额，覆盖
  "实际台费低于已付押金，不退差额"（H.4）的场景——这种场景下 Amount paid 会显示大于 actual_table_fee 的
  已收押金，这是如实反映"实际收了多少钱"，不是展示 bug。
- 不新增字段、不改 controller——`booking` 已经在模板 context 里，`actual_table_fee`/`balance_amount`/
  `balance_method` 都是 `booking.*` 上现成的字段。
- 目前没有"结算完成"通知邮件，`booking_email` 模板只在创建预约等待押金时发送（那时 state 必是
  `pending`/`confirmed`，不可能是 `done`），所以邮件模板不用改。

## 2. task-4.5-v1-03（My Bookings 列表对齐，纯 CSS/模板结构）

**现状**：`addons/qclub_billiard/views/my_account_templates.xml` 里 `qclub_billiard.my_billiard` 的
"My bookings" 分区，每一行是：
```xml
<div class="o_qclub_booking_details">
    <p class="small text-muted">time · table</p>
    <p class="small text-muted">Booked on ...</p>
    <div class="o_qclub_row_actions">View booking date [, Cancel booking] [, Find players]</div>
</div>
```
CSS（`booking.scss`）：`.o_qclub_booking_details { display:flex; justify-content:space-between; flex-wrap:wrap; }`。
三个宽度不固定的子元素（时间文本长度不定、是否有 Cancel/Find players 链接也不定）用 `space-between` 分散对齐，
换行位置和每个元素的水平位置逐行不一样，视觉上就对不齐（见验收截图红圈）。

**修复**：把前两个 `<p>` 包进一个新的容器 `<div class="o_qclub_booking_info">`，让
`.o_qclub_booking_details` 下永远只有两个 flex 子元素（左边信息块、右边操作区），不再受里面内容多少影响：

```xml
<div class="o_qclub_booking_details">
    <div class="o_qclub_booking_info">
        <p class="small text-muted"><span t-out="item['time']"/> · <span t-out="item['table']"/></p>
        <p class="small text-muted">Booked on <span t-out="item['posted']"/></p>
    </div>
    <div class="o_qclub_row_actions">
        ...（内容不变）
    </div>
</div>
```

CSS 调整（`booking.scss`）：
```scss
.o_qclub_booking_details { display: flex; justify-content: space-between; align-items: flex-start; flex-wrap: wrap; gap: 0.25rem 1rem; }
.o_qclub_booking_info p { margin: 0; }
.o_qclub_booking_info { min-width: 0; }
```
（`.o_qclub_booking_details p { margin: 0; }` 原来的全局 `.o_qclub_account_row p { margin: 0; }` 规则仍然
覆盖这里新加的 `p`，不用重复定义，上面列出来是为了说明效果，Codex 实现时不用是否要加由实际 CSS 继承情况决定，
不要为了保险加重复规则。）

只改这一个分区（`qclub_my_bookings`），posts/requests/messages 三个分区结构不同、没有这个问题，不要动。

## 二、数据模型 `qclub.booking`

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | Char，只读 | 预约编号，由 `ir.sequence` 生成，如 `QB2026-00001`；数据库唯一约束（BK-011） |
| `table_id` | Many2one `qclub.table`，必填 | `ondelete="restrict"` |
| `website_id` | 关联 `table_id.website_id`，存储 | BK-012；用于以后的记录规则 |
| `partner_id` | Many2one `res.partner`，必填 | 顾客（电话预约时由员工选或新建联系人） |
| `start` / `end` | Datetime（UTC），必填 | |
| `duration_hours` | Integer，计算并存储 | `(end − start)` 的小时数 |
| `business_date` | Date，计算并存储 | 所属营业日（跨午夜的预约归开始那一天的营业时段），用于列表分组、日历和以后的网格 |
| `state` | Selection | 见第四节 |
| `lock_expire` | Datetime | BK-007 |
| `hourly_price`、`deposit_ratio`、`free_cancel_hours`、`no_show_wait_minutes` | 快照，只读 | CFG-003；创建后不随配置变化 |
| `currency_id` | 关联网站公司币种（AUD） | |
| `table_fee`、`deposit_amount` | Monetary，存储 | BK-009；创建时按快照计算 |

**表单输入方式**：员工在表单里选桌台、填**开始时间**和**小时数**，结束时间自动算出（不用自己算跨午夜的结束时间）。

## 三、校验规则

在创建，以及修改桌台 / 起止时间时执行（英文提示）：

1. **整点与时长（BK-001）**：开始、结束在 `Australia/Adelaide` 本地时间必须是整点（注意阿德莱德是半小时时区，本地整点对应 UTC 的 :30）；小时数为整数，且 `1 ≤ 小时数 ≤ max_consecutive_hours`
2. **营业时段（BK-002）**：整个预约必须落在某一个营业时段内。只用任务 1.2 的 `_get_business_intervals`：取开始时刻的本地日期以及前一天（覆盖跨午夜那一段）的营业时段，找到包含 `[start, end)` 的那一段；找不到则拒绝。找到的那段所属日期即 `business_date`
3. **时间范围（BK-003）**：开始时间必须晚于当前时间；`business_date` 不得晚于"今天（阿德莱德）+ max_advance_days"
4. **桌台启用（TBL-003）**：调用 1.1 的 `table._check_bookable()`；只在新建、换桌时检查，所以停用桌台上的已有预约不受影响
5. **时段冲突（BK-006）**：同一桌台上，时间重叠且状态为"有效占用"（待付押金、已确认、已到店）的预约不能同时存在；Python 层检查，给出英文提示。任务 1.4 会再加数据库排他约束兜底并处理并发

**快照与金额（CFG-003、BK-009、TBL-005）**：创建时从桌台和该网站的配置（`qclub.config` 以 sudo 调用 `_get_for_website`）复制快照字段；`table_fee = hourly_price × duration_hours`，`deposit_amount = currency.round(table_fee × deposit_ratio / 100)`。之后修改配置或桌台单价都不影响已有预约。修改已有预约的时长时，按**该预约自己的快照单价**重算金额。

## 四、状态与流转（BK-007、BK-010、ADM-004）

| 值 | 界面名称 | 占用时段 |
|---|---|---|
| `pending` | Awaiting Deposit（待付押金） | 是 |
| `confirmed` | Confirmed（已确认） | 是 |
| `arrived` | Arrived（已到店） | 是 |
| `done` | Completed（已完成） | 否 |
| `cancelled` | Cancelled（已取消） | 否 |
| `expired` | Expired（已过期） | 否 |
| `no_show` | No-show（未到场） | 否 |

允许的流转（BK-010），其余一律报错，包括直接写 `state` 字段：

```
pending   → confirmed / expired / cancelled
confirmed → arrived / cancelled / no_show
arrived   → done
```

- 新建一律为 `pending`，`lock_expire = 创建时间 + lock_minutes`（BK-007）；不能在新建时直接指定其他状态
- 表单按钮：Confirm、Mark Arrived、Complete、Cancel、No-show，只在当前状态允许时显示；`expired` 只由系统（任务 1.4 的定时任务）设置，没有按钮
- 本任务"未到场"按钮只做状态流转；"超过等待时长才能标记"、押金没收和管理员恢复属于阶段 4（NS-001/002）

## 五、权限与界面

| 模型 | Billiard Staff | Billiard Manager |
|---|---|---|
| `qclub.booking` | 读、写、建（不能删） | 读、写、建（不能删） |

预约不允许删除，只能取消，保留记录便于对账（以后阶段 4 的退款、没收都依赖这些记录）。

菜单 **Billiards → Bookings**（员工可见，序号 15，位于 Tables 之后）。视图（ADM-002）：
- 列表：编号、营业日、桌台、顾客、开始、结束、小时数、押金、状态（带颜色标记）
- 日历：按开始 / 结束显示，按桌台着色
- 搜索：按状态筛选（预置 "Active" = 有效占用三种状态）、按桌台、按营业日；可按状态、桌台、营业日分组
- 表单：顶部状态栏和状态按钮；快照与金额区域只读
